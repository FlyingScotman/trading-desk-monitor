# Desk Monitor на рабочем компьютере (Windows)

Desk Monitor (бэкенд `desk`: снапшоты рынка из хаба, отчёты банка через приватный адаптер, оценка книг через core, EOD-прогоны, Desk Monitor и Scenario Lab в браузере) приходит на рабочий компьютер **одним zip-архивом**. В архиве уже есть Python 3.11, все пакеты и встроенный PostgreSQL: ставить ничего не нужно, интернет для установки не нужен, права администратора не нужны. Архив распаковывается в любую папку, запускается двойным щелчком по `start.bat`, а дальше всё настраивается в браузере.

Старый прототип `tdm` ставится по [`INSTALL_WINDOWS.md`](INSTALL_WINDOWS.md); эти установки независимы.

## 1. Что в архиве

```
DeskMonitor\
  start.bat          запуск: установка (при первом запуске и после обновления), сервер, браузер
  stop.bat           остановить сервер и встроенный PostgreSQL этой папки
  update_daily.bat   один цикл автопилота сейчас (desk cycle): хаб, отчёты, EOD
  desk.bat           любая команда desk из командной строки (диагностика)
  INSTALL.txt        короткая инструкция
  VERSION            версия архива: <версия>-<дата коммита>-<коммит>
  MANIFEST.sha256    контрольная сумма каждого файла
  python\            Python 3.11 для Windows x64 (python-build-standalone)
  wheelhouse\        все пакеты (.whl) под Windows / Python 3.11 и requirements.txt
  app\               deskctl.py (логика .bat-файлов), prototypes\, frontend\dist\, examples\, эта инструкция
  adapter\           приватный адаптер, если архив собран с ним (в публичном репозитории его нет)
```

При первом запуске рядом появляется `env\` — виртуальное окружение Python, собранное из `python\` и `wheelhouse\`. Данные и настройки хранятся **не в этой папке**, а в `%LOCALAPPDATA%\DeskMonitor` (раздел 7), поэтому папку программы можно удалить или заменить новой версией.

## 2. Собрать архив (дома)

Нужны клон репозитория, [uv](https://docs.astral.sh/uv/), `git`, Python 3.11 с `pip` и интернет (PyPI и GitHub).

```bash
python3.11 backend/tools/build_windows_bundle.py
python3.11 backend/tools/build_windows_bundle.py --adapter-zip ~/private/adapter.zip
```

- без флагов — архив без приватного адаптера: `dist/DeskMonitor-<версия>.zip`;
- `--adapter-zip <zip>` — положить в `adapter\` пакет приватного адаптера из этого zip (в zip ровно один пакет — папка с `__init__.py`; README рядом с ним тоже копируется). Имя архива получает суффикс `-with-adapter`: такой архив **не публикуется**, он только для рабочей машины;
- `--allow-dirty` — собрать из незакоммиченных изменений (без него скрипт отказывается). К версии добавляется `-dirty<время сборки>`, поэтому `start.bat` переустановит окружение даже при том же коммите;
- `--cache <папка>` — куда кэшировать скачанный Python (по умолчанию `dist/cache`); `--python-release`, `--python-version` — другой выпуск python-build-standalone; `--no-python` — архив без Python (тогда на рабочей машине нужен `py -3.11`);
- если `python3.11` без `pip`: `uv run --no-project --python 3.11 --with pip python backend/tools/build_windows_bundle.py`.

Что делает скрипт:
1. берёт точные версии зависимостей из `backend/uv.lock` плюс `pgserver` (встроенный PostgreSQL), разрешает их для Windows и скачивает колёса win_amd64 / CPython 3.11;
2. собирает колёса `desk-backend`, `trading-desk-monitor` и `rub-fixed-income-core` (с GitHub, ровно тот коммит, что закреплён в `backend/pyproject.toml`);
3. **проверяет**, что `wheelhouse\` ставится на Windows / Python 3.11 без интернета (`pip install --dry-run --no-index --platform win_amd64` и `uv pip install --dry-run --python-platform x86_64-pc-windows-msvc`);
4. скачивает Python (архив `install_only` для `x86_64-pc-windows-msvc`), сверяет его sha256 с файлом `SHA256SUMS` выпуска и кладёт в `python\` без отладочных символов и Tk;
5. кладёт `app\`, `adapter\`, `.bat`-файлы (с переводами строк CRLF), `INSTALL.txt`, `VERSION`, `MANIFEST.sha256` и печатает путь, размер и sha256 архива.

Архив — около 55 МБ, 2600 файлов.

## 3. Перенести и распаковать

1. Скопируйте zip на рабочую машину (как разрешено). Сверьте контрольную сумму с напечатанной при сборке:
   ```bat
   certutil -hashfile DeskMonitor-<версия>.zip SHA256
   ```
2. Если файл пришёл по почте или из интернета: правой кнопкой по zip → **Свойства** → галочка **Разблокировать** → ОК. Иначе Windows пометит каждый распакованный файл как «из интернета» и будет спрашивать про каждый запуск (или заблокирует).
3. Распакуйте в свою папку на **локальном** диске, лучше с коротким путём без пробелов и русских букв, например `C:\DeskMonitor`. Не в `Program Files` (туда нельзя писать без администратора) и не на сетевой диск. Проводник («Извлечь всё») создаёт вложенную папку — это нормально: рабочая папка та, где лежит `start.bat`. Из командной строки без вложенной папки:
   ```bat
   tar -xf DeskMonitor-<версия>.zip -C C:\
   ```
   (`tar` встроен в Windows 10 и новее; в архиве уже есть верхняя папка `DeskMonitor`, получится `C:\DeskMonitor`).

## 4. Первый запуск

Двойной щелчок по `start.bat`. Он:

1. создаёт окружение `env\` из `python\` и ставит пакеты из `wheelhouse\` **без интернета** (`pip install --no-index --find-links wheelhouse -r wheelhouse\requirements.txt`), 1–3 минуты;
2. создаёт базу (`desk db-migrate`): встроенный PostgreSQL при первом запуске создаёт кластер в `%LOCALAPPDATA%\DeskMonitor\pg` (до минуты) и дальше работает в фоне;
3. запускает сервер (`desk serve`) на `127.0.0.1:8000` и, когда он ответит, открывает браузер: при первом запуске — страницу настроек `http://127.0.0.1:8000/settings.html`, потом — Desk Monitor `http://127.0.0.1:8000/desk-monitor.html`.

Окно `start.bat` не закрывайте: пока оно открыто, Desk Monitor работает. Всё, что сервер пишет в окно, дублируется в журнал `%LOCALAPPDATA%\DeskMonitor\logs\serve.log`. Остановить: закрыть окно, `Ctrl+C` в нём или `stop.bat`. Повторный `start.bat`, когда сервер уже работает, просто открывает браузер.

Следующие запуски ничего не ставят и стартуют за несколько секунд. Окружение пересобирается само, только если сменилась версия архива или папка была перенесена (окружение Python нельзя перенести: оно помнит свой путь).

Сервер слушает только `127.0.0.1` (эту машину). У API нет авторизации, поэтому открывать его в сеть не нужно.

## 5. Настроить (страница «Настройки»)

`http://127.0.0.1:8000/settings.html` (или ссылка «Настройки» в шапке Desk Monitor). Один раз:

1. **Хаб**: адрес (`https://…`, его даёт владелец; в репозитории его нет) и токен (scope `snapshots`), кнопка проверки связи. Токен сохраняется отдельным файлом `hub_token` в папке данных и обратно не показывается. Здесь же прокси (`https_proxy`), если он не задан в Windows, и PEM-файл корневого сертификата прокси (`hub_ca_bundle`), если хаб не открывается из-за TLS (раздел 10).
2. **Папки отчётов**: куда приходят утренние отчёты банка (с подпапками или без).
3. **Адаптер**: если архив собран с адаптером, он подхватывается из `adapter\` сам; другой путь можно указать здесь. Ниже — файлы настроек адаптера (например, соответствие книг): редактор JSON с шаблоном, проверка, сохранение. Файлы лежат в `%LOCALAPPDATA%\DeskMonitor\adapter-config`.

Дальше работает **автопилот** (внутри `desk serve`): раз в минуту забирает новые снапшоты с хаба, подхватывает новые отчёты из папок, запускает EOD по каждой рабочей дате, у которой изменились входные данные, — и Desk Monitor показывает свежие риски. Состояние — значок автопилота в шапке Desk Monitor, кнопка «Обновить» запускает цикл сразу.

Настройки хранятся в `%LOCALAPPDATA%\DeskMonitor\settings.json` и действуют без перезапуска. Приоритет: переменные окружения `DESK_*` > `settings.json` > файл `desk.env` (если положить его в папку данных) > значения по умолчанию. Действующие значения: `desk.bat config` (раздел 9).

## 6. Каждый день

Ничего делать не нужно, пока открыт `start.bat`. Чтобы Desk Monitor запускался сам после входа в Windows, положите ярлык на `start.bat` в папку автозагрузки (`Win+R` → `shell:startup`).

`update_daily.bat` — один цикл автопилота прямо сейчас (`desk cycle`), без сервера; журнал `logs\cycle.log`. Нужен, если сервер не держат открытым. Цикл:

1. снапшоты последних дат из хаба (`autopilot_sync_last`, по умолчанию 5) и тех дат, что нужны позициям в базе и отчётам в папках; уже скачанные не скачиваются снова. Не старше окна «Брать отчёты не старше, дней» (`inbox_lookback_days`, по умолчанию 10), не больше `autopilot_sync_last` + 3 дат за цикл (остальные — в следующем), дату, которой нет на хабе, повторно не спрашивают 6 часов. Если задана папка drop, принимаются и снапшоты из неё;
2. новые отчёты из папок (`desk inbox scan`). Файлы, изменённые раньше окна `inbox_lookback_days`, даже не читаются (только дата файла); файлы с датой отчёта старше окна один раз помечаются `ignored_too_old` и больше не предлагаются (если окно увеличить — будут прочитаны). Поэтому папку с архивом отчётов за годы можно указывать как есть. Загрузка истории за прошлые даты будет отдельной командой с явным диапазоном дат (слайс S8). Прерванный скан (`stop.bat`) при следующем запуске продолжается с того места, уже прочитанные файлы не читаются заново. Ход цикла («Скан отчётов: 37 из 412», «Загрузка снимков: 2 из 5», «EOD 16.10: 1 из 3») виден в значке автопилота Desk Monitor;
3. EOD-прогон каждой недавней даты, у которой ещё нет прогона или изменились входные данные (новая версия позиций, исправленный снапшот). Даты и праздники берутся из календаря снапшотов, передавать дату не нужно;
4. история котировок для графиков цен и доходностей: по 5 старых дат хаба за цикл, от новых к старым, на глубину `history_days` (по умолчанию 260 рабочих дней, около года; 0 — только даты из кэша). В базу попадают только котировки и КБД, сами снапшоты этих дат не сохраняются (около 100 МБ в базе за год вместо ~1 ГБ файлов). Год истории набирается примерно за час работы сервера. Ход виден в значке как «История котировок: 2 из 5».

Параметры передаются в `desk cycle`: `update_daily.bat --date 2026-10-16` — дополнительно подтянуть и при изменениях пересчитать эту дату, `update_daily.bat --no-hub` — без обращения к хабу (снапшоты только из кэша и папки drop). Код возврата 1 — какой-то шаг завершился ошибкой (она напечатана); остальные шаги при этом выполнены на том, что есть в кэше.

Одновременно выполняется только один цикл: если в этот момент цикл уже идёт (автопилот в `start.bat` или другой `update_daily.bat`), `update_daily.bat` ничего не делает и печатает `cycle: skipped - another cycle running` (код возврата 0). Блокировка — файл `cycle.lock` в папке данных; после аварийного завершения процесса она снимается сама.

По расписанию через Планировщик заданий (обычные права):

```bat
schtasks /create /tn "Desk Monitor daily" /sc weekly /d MON,TUE,WED,THU,FRI /st 08:30 /tr "\"C:\DeskMonitor\update_daily.bat\""
```

- `/tn` — имя задачи; `/sc weekly /d MON,…,FRI` — по будням; `/st 08:30` — время; `/tr` — что запускать (путь в кавычках, кавычки внутри экранированы `\"`). При ошибке `update_daily.bat` ждёт не больше минуты и не требует нажатия клавиши.

## 7. Где что лежит

| Что | Где |
|---|---|
| программа | папка, куда распакован архив (`start.bat`, `python\`, `env\`, …) |
| данные и настройки (`DESK_HOME`) | `%LOCALAPPDATA%\DeskMonitor` = `C:\Users\<имя>\AppData\Local\DeskMonitor`; если в этом пути есть русские буквы (имя пользователя кириллицей) — `C:\DeskMonitorData`, доступная только вам: встроенный PostgreSQL не работает с такими путями |
| настройки | `settings.json`, токен `hub_token`, файлы адаптера `adapter-config\` |
| база (встроенный PostgreSQL) | `pg\` |
| снапшоты, копии отчётов, отчёты сверки | `snapshots\`, `inbox-archive\`, `reports\` |
| журналы | `logs\serve.log` (сервер), `logs\cycle.log` (`update_daily.bat`): при 20 МБ прежний журнал становится `*.log.1`; `logs\autopilot.log` — шаги каждого цикла автопилота (до 2 МБ, плюс три прежних `*.log.1`–`*.log.3`) |

Другое место для данных — переменная `DESK_HOME`, путь латиницей (с русскими буквами `start.bat` откажется запускаться: PostgreSQL на них спотыкается). Папка программы тоже должна быть латиницей и **без пробелов**, иначе `start.bat` попросит её перенести:

```bat
setx DESK_HOME D:\DeskData
```

`setx` сохраняет переменную для вашей учётной записи; действует в окнах, открытых после этого (перезапустите `start.bat`). Старые данные перенесите в новую папку сами, остановив Desk Monitor (`stop.bat`).

Что `start.bat` задаёт процессам `desk` (только если переменная ещё не задана): `DESK_HOME` (выше), `DESK_STATIC_ROOT` = `app\` этой папки, `DESK_DEFAULT_PRIVATE_ADAPTER` = пакет в `adapter\` (если он есть; путь из настроек важнее), `DESK_ENV_FILE` = `%DESK_HOME%\desk.env` (если такой файл есть). Порт — переменная `DESK_PORT` (по умолчанию 8000) или `start.bat --port 8001`.

## 8. Обновление

1. Остановите старую версию: `stop.bat` в её папке (или закройте окно `start.bat`).
2. Распакуйте новый архив в любую папку — новую или поверх старой — и запустите **её** `start.bat`. Он увидит другую версию в `VERSION`, пересоберёт `env\` из нового `wheelhouse\` (1–3 минуты), применит новые миграции базы и запустит сервер.
3. Настройки, токен, база и снапшоты остаются в `%LOCALAPPDATA%\DeskMonitor`: ничего переносить не нужно. Старую папку (если новая — другая) можно удалить.

Распаковка поверх работающей версии не удастся (файлы заняты) — сначала шаг 1.

## 9. Диагностика из командной строки

`desk.bat` запускает любую команду `desk` с теми же настройками, что и `start.bat` (в окне командной строки, из папки программы):

```bat
cd /d C:\DeskMonitor
desk.bat config
desk.bat hub-check
desk.bat runs
desk.bat inbox status
desk.bat import-drop
```

- `config` — действующие настройки (токен замаскирован), откуда взят прокси;
- `hub-check` — версия хаба, проверка токена, последний снапшот и его возраст;
- `runs` — EOD-прогоны в базе: дата, тип, статус;
- `inbox status` — отчёты из папок: принятые, отклонённые и почему;
- `import-drop` — принять снапшоты, положенные руками в папку drop (раздел 10).

Первый прогон без реальных отчётов (синтетическая книга: реальные публичные выпуски, выдуманные количества): `desk.bat eod --date <дата последнего снапшота> --book app\examples\test_book.csv`.

## 10. Если что-то не так

Сообщение об ошибке остаётся в окне `start.bat` (окно ждёт нажатия клавиши). Журнал сервера — `%LOCALAPPDATA%\DeskMonitor\logs\serve.log`.

| Симптом | Причина / что делать |
|---|---|
| Windows: «Система Windows защитила ваш компьютер» / «Не удаётся проверить издателя» при каждом запуске | архив не разблокирован до распаковки (раздел 3, шаг 2). Удалите папку, разблокируйте zip, распакуйте снова |
| «Эта программа заблокирована групповой политикой» / `Access is denied` на `python.exe` | политика запрещает запуск программ из профиля пользователя (AppLocker). Распакуйте в разрешённое место (например, `C:\DeskMonitor`) или попросите ИТ разрешить `python\python.exe` и `env\` этой папки |
| `Python not found: python\ is missing` | распакован не весь архив: распакуйте заново |
| `pip не смог установить пакеты из wheelhouse` | архив распакован не полностью или повреждён: сверьте sha256 (раздел 3) и распакуйте заново |
| `Не удалось удалить старое окружение … env` | файлы заняты: закройте окна Desk Monitor, запустите `stop.bat`, повторите. Не помогает — удалите папку `env\` руками (данные не там) |
| `Порт 8000 занят другой программой` | `netstat -ano \| findstr :8000` — последняя колонка PID, найдите его в Диспетчере задач. Или другой порт: `set DESK_PORT=8001`, затем `start.bat` из того же окна (или `start.bat --port 8001`) |
| `Порт 8000 занят другим экземпляром Desk Monitor` | работает другая (обычно старая) версия из другой папки: `stop.bat` в её папке или закройте её окно |
| проверка хаба: таймаут или `Connection refused` | не задан прокси. Python берёт его из переменной `HTTPS_PROXY`, а если её нет — из **статических** настроек прокси Windows (Свойства браузера → Подключения → Настройка сети → «Прокси-сервер»). Скрипт автонастройки (PAC, «Использовать сценарий автоматической настройки») Python не понимает: узнайте у ИТ адрес прокси и впишите его в настройки (`https_proxy`, вида `http://proxy.local:8080`) или `setx HTTPS_PROXY http://…` |
| проверка хаба: `407 Proxy Authentication Required` | прокси требует входа; в ошибке видно, какого (`прокси требует: Negotiate, NTLM`). Python умеет только Basic, поэтому способ подключения «Авто» (по умолчанию) сам переходит на `curl.exe` из Windows 10/11, который входит в прокси под текущей учётной записью Windows (NTLM/Kerberos) и проверяет сертификаты по хранилищу Windows; можно выбрать и «curl Windows» явно (`hub_transport`). Прокси указывайте без логина (`http://host:port`); логин (`ДОМЕН\логин`) и пароль прокси — только если вход по учётке Windows не проходит. Если не помогло — папка drop: дома `desk sync --last 2`, файлы `<snapshot_id>.json.gz` из кэша снапшотов — на флешку; на работе в настройках укажите папку drop (`snapshot_drop`) и положите файлы туда; их примет автопилот или `desk.bat import-drop` (каждый файл проверяется по sha256, испорченный отклоняется с причиной) |
| проверка хаба: `CERTIFICATE_VERIFY_FAILED` | Desk Monitor проверяет сертификат хаба через хранилище сертификатов Windows (как браузер, включая корневые сертификаты, которые Windows догружает сама или которые ставит ИТ групповой политикой). Ошибка значит, что прокси подменяет TLS-сертификат, а его корневого сертификата нет в хранилище Windows. Попросите у ИТ корневой сертификат прокси в формате PEM (Base-64 `.cer`) и укажите путь в настройках (`hub_ca_bundle`). Этот файл **заменяет** системное хранилище |
| `PostgreSQL не успел запуститься … Повтор 2 из 3` при первом запуске | встроенный PostgreSQL (pgserver) ждёт запуска сервера только 10 секунд, а при первом запуске антивирус может дольше проверять `postgres.exe` и его библиотеки. `start.bat` сам повторяет `desk db-migrate` до 3 раз с паузой 5 секунд — обычно вторая попытка проходит. Если не прошли все три, просто запустите `start.bat` ещё раз; не помогает — следующая строка |
| `desk db-migrate не прошёл` / PostgreSQL не стартует (`Failed to start server`, `Timeout starting server`) | смотрите журнал `%LOCALAPPDATA%\DeskMonitor\pg\log`. Частые причины: **антивирус** блокирует `postgres.exe` в `env\Lib\site-packages\pgserver\pginstall\bin` (попросите ИТ разрешить эту папку); окно запущено «от имени администратора» (PostgreSQL так не работает — запускайте обычным двойным щелчком); пробелы или русские буквы в пути к данным — задайте `DESK_HOME` (раздел 7) или в пути к программе — перенесите её в `C:\DeskMonitor`; после сбоя остался `pg\postmaster.pid` — если в Диспетчере задач нет процессов `postgres.exe`, удалите этот один файл и повторите |
| PostgreSQL так и не заработал | запасной вариант — отдельный PostgreSQL (например, zip-архив бинарников EDB «PostgreSQL binaries», без установщика): `initdb`, `pg_ctl start`, база `desk`, и в настройках `store_url` = `postgresql://<пользователь>:<пароль>@127.0.0.1:5432/desk` (или переменная `DESK_STORE_URL`). Тогда встроенный PostgreSQL не используется |
| `desk: the desk store is not migrated` | `desk.bat db-migrate` |
| `Сервер остановился с ошибкой` | подробности — в последних строках окна и в `logs\serve.log`. Если окно уже закрыто, запустите `start.bat` снова и посмотрите сообщение |
| нужно переставить окружение начисто | `stop.bat`, удалить папку `env\` (данные не там), `start.bat` |
