# Данные для центрального сервиса: что собрать и загрузить

Список того, что нужно добыть на вашей стороне, чтобы `tdm` работал как центральный источник данных для мониторов. История — **1 год** (~250 рабочих дней). Позиции — **ежедневными снэпшотами** на конец дня: сделки в реальном времени не нужны.

Как читать документ:
- **§1** — минимальный набор, без которого мониторы не заработают, и что даёт каждый следующий уровень.
- **§2** — правила, которые важнее самих данных: единый источник, стабильные ключи, единицы измерения.
- **§3** — как загружать.
- **§4** — подробная спецификация каждого набора. Генерируется из `tdm/datasets.py`, поэтому всегда совпадает с тем, что принимает загрузчик.

Шаблоны CSV лежат в `contract/csv/` (заголовок и строка-пример, открываются в Excel). Как сервис хранит эти данные и что отдаёт — в `docs/SERVICE_DATA_MODEL.md`.

## 1. Что собирать в первую очередь

### Уровень A — мониторы работают на сегодняшнем дне

| Набор | Глубина |
|---|---|
| `books`, `issuers`, `issuer_ratings` (текущий рейтинг), `curves` | текущее состояние |
| `instruments` — облигации в позиции | текущее состояние |
| `otc_deals` — живые IRS, XCCY, CDS, FX | текущее состояние |
| `positions`, `funding` | сегодня и предыдущий рабочий день (новые сделки и изменения видны через сравнение) |
| `md_curves`, `md_fx`, `md_fixings`, `md_bond_quotes` | сегодня и вчера (изменения за день) |
| *1.3*: `funding_rates`, `cash_balances`, `md_fx_cbr`, `cbr_meetings`; `book_type` / `entity` в `books` | §4а: фондирование по конвенциям организации, два базиса FX, сценарии кэрри |

Плюс результаты расчётов по сегодняшнему дню от расчётного сервиса: риски и PnL explain (см. `docs/DATA_CONTRACT.md`).

### Уровень B — история и исторические сценарии (1 год)

| Набор | Что даёт |
|---|---|
| `md_curves`, `md_fx`, `md_fixings`, `md_bond_quotes` за год | исторические сценарии «худший день / худшие 10 дней»; история выпуска (цена, доходность, спред к кривой); графики уровней и спредов; волатильность |
| `issuer_ratings` — все изменения за год | спред-шоки по рейтинговым корзинам на исторические даты |
| `positions`, `funding` за год | расчётный сервис может пересчитать риски и PnL за любой день; история объёмов, книг, концентраций |
| `pnl_official` за год | история PnL и разрывов (break) |
| `desk_history` | итоги деска по дням, **если** расчётный сервис не будет пересчитывать прошлое; иначе заполнится сам |

### Уровень C — точность и удобство

| Набор | Что даёт |
|---|---|
| `bond_cashflows` | лестница потоков, ближайшие купоны и оферты; переоценка у расчётного сервиса |
| `trades` | PnL новых сделок (`new_trades`), точная подсветка «сегодня» |
| `counterparties`, `calendar` | подписи контрагентов, корректные окна в рабочих днях |
| `md_cds` | переоценка CDS-книги по рынку, а не по прокси от облигаций |

### Облигации: таблица по выпускам и история выпуска

Что нужно для вкладки «Облигации» Desk Monitor, виджетов «Облигации» и «История выпуска» Widget Board и мер по облигациям в Pivot Studio:

| Что видно в мониторе | Набор и поля | Глубина | Уровень |
|---|---|---|:-:|
| выпуск, ISIN, эмитент, рейтинг, купон, погашение, **оферта** | `instruments`: `instrument_id`, `isin`, `name`, `coupon_type`, `coupon_rate`, `coupon_freq`, `index_name`, `margin`, `maturity`, **`offer_date`**; `issuers`, `issuer_ratings` | все бумаги, бывшие в позиции за год | A |
| цена, НКД, доходность, дюрация, спред-дюрация, выпуклость, расчётный спред и его тип | результат расчётного сервиса: `position.price`, `accrued`, `ytm`, `mdur`, `spr_dur`, `convexity`, `spread_bp`, `spread_type`, `spread_curve`, `yield_date` (`docs/DATA_CONTRACT.md` §4.3.5) | сегодня | A |
| позиция и риск: номинал, MV, DV01, CS01, PnL дня | `positions` (снэпшот) → расчётный сервис → `position` | сегодня | A |
| **спред к выбранной кривой** (ОФЗ, RUONIA, КС, SOFR, CNY, €STR) | монитор считает сам из `ytm` и кривой → нужны `md_curves` по **всем** кривым, к которым хотят смотреть спред | сегодня | A |
| Δ цены, Δ доходности, Δ спреда за день | `md_bond_quotes`: `clean_price`, `ytm`, `z_spread_bp` — **сегодня и предыдущий рабочий день**; для Δ спреда к кривой — `md_curves` за вчера | 2 дня | A |
| **история выпуска**: цена, НКД, доходность | `md_bond_quotes`: `clean_price`, `accrued`, `ytm` | каждый рабочий день за год | B |
| история: ставка кривой на сроке выпуска и спред к ней | `md_curves` за год + `instruments.offer_date` / `maturity` (срок на каждую дату) | за год | B |
| история: расчётный спред (Z / G / DM) | `md_bond_quotes`: `z_spread_bp`, `g_spread_bp` | за год | B |
| история: позиция по выпуску | `positions`: `instrument_id`, `face_amount` (или `quantity`) | каждый рабочий день за год | B |
| оборот (подсказка о ликвидности) | `md_bond_quotes.volume_rub` | за год | C |

Правила, без которых история выпуска будет врать:
1. **Одна база доходности.** `ytm` в котировках и в расчёте — к ближайшей оферте, пока она впереди, иначе к погашению. Если источник котировок считает к погашению, а расчёт к оферте, спред к кривой будет «прыгать».
2. **Один тип спреда.** `z_spread_bp` в котировках — того же типа, что `spread_type` в расчёте: Z для фикса, DM к индексу для флоатера. Источник — один на весь год (§2).
3. **Цены чистые**, в % номинала. НКД отдельно, тоже в % номинала.
4. **Один ключ бумаги** везде: `instrument_id` в `instruments`, `positions`, `md_bond_quotes` и в результате расчёта (`position.instrument_id` или ISIN).
5. **Котировки по всем бумагам, что были в позиции за год**, а не только по сегодняшним. Иначе по закрытой позиции нет истории. Желательно добавить и бенчмарки эмитентов.
6. **Пропуск — это пропуск.** Нет котировки за день — строки нет; график покажет разрыв. Не протягивать прошлую цену.
7. **Оферта меняет срок.** После прохождения оферты обновите `offer_date` в `instruments` (следующая оферта или пусто). Срок в истории считается по ней на каждую дату.

### Кому что нужно

| Потребитель | Наборы |
|---|---|
| **Мониторы напрямую** (через API сервиса) | справочники, позиции, фондирование, рынок (уровни, изменения, ряды), официальный PnL, исторические сценарии |
| **Расчётный сервис** (вход в либу) | `instruments`, `bond_cashflows`, `otc_deals`, `positions`, `funding`, `md_*`. Может брать их из `tdm` через API — тогда монитор и расчёт гарантированно видят одно и то же |
| **Результаты расчётов** (пишет расчётный сервис, мониторы читают) | key-rate DV01, CS01, FX-дельта, **вторые производные** (матрица гамм: ставки×ставки, ставки×спред, спред×спред, курс×ставки, или минимум — выпуклость облигаций), JTD, MV, PnL explain, полная переоценка сценариев — `docs/DATA_CONTRACT.md` §4.3 |

### Объёмы для оценки

Порядок величины при ~100 позициях, ~30 бумагах в котировках и 6 кривых по ~12 узлов:

| Набор | Строк в день | Строк за год |
|---|---|---|
| позиции | 100 | 25 тыс. |
| кривые | 72 | 18 тыс. |
| котировки облигаций | 30–300 | 8–75 тыс. |
| курсы и фиксинги | около 15 | около 4 тыс. |

Всё вместе — единицы мегабайт; SQLite справляется с запасом. При 10 тыс. позиций — около 2,5 млн строк позиций за год, тоже нормально.

## 2. Правила для данных (важнее самих данных)

1. **Один источник на ряд на весь год.**
   - Курсы — **два ряда** (контракт 1.3): рыночный (`md_fx`, внешние котировки на ~19:00, подаются изнутри) и ЦБ (`md_fx_cbr`, по дате действия). Внутри каждого ряда источник не меняется. USD и EUR на МосБирже не торгуются с июня 2024 — «MOEX TOM close» для них не годится.
   - Кривая — один тип ставок (zero или par) и одна методика.
   - Переключение источника посреди года создаёт ложные «шоки» в исторических сценариях.
2. **Стабильные ключи.** Неизменны между днями и между наборами:
   - `position_id`: для бумаг удобно `book_id|ISIN`, для OTC — номер сделки;
   - `deal_id`, `instrument_id` (лучше ISIN), `issuer_id` (лучше ИНН или LEI), `book_id`.
3. **Снэпшот — полный.** Файл позиций за дату содержит **все** позиции книги на эту дату. Загрузка заменяет срез целиком по паре (дата, книга): позиция, отсутствующая в файле, считается закрытой. Можно грузить один файл на все книги или файл на книгу.
4. **Даты.** `YYYY-MM-DD` (допускается `ДД.ММ.ГГГГ`). Дата среза — **рабочий день рынка**, на который сняты позиции и цены. Рыночные данные и позиции должны совпадать по датам.
5. **Единицы.**
   - ставки, доходности, купоны — в **%** (14.5);
   - спреды — в **б.п.**;
   - цены облигаций — в **% от номинала**;
   - курсы — **RUB за 1 единицу** валюты;
   - суммы — в валюте инструмента, если в имени поля нет `_rub`.
6. **Знаки.** Длинная позиция и размещение — `+`; шорт и привлечение — `−`. PnL: `+` — прибыль.
7. **Узлы кривых.** Любые сроки (`tenor_years`), но одинаковый набор на все даты и покрытие от 1М до 20Л. Сервис сам интерполирует на 11 пилларов монитора: 1M 3M 6M 1Y 2Y 3Y 5Y 7Y 10Y 15Y 20Y+.
8. **Фиксированные ключи монитора** (пока UI ссылается на них по имени):
   - кривые: `RUB OFZ`, `RUB RUONIA`, `RUB KEY`, `USD SOFR`, `CNY`, `EUR ESTR`;
   - валюты: `RUB`, `USD`, `CNY`, `EUR`;
   - индексы: `КС`, `RUONIA`, `RUSFAR O/N`, `RUSFAR CNY`, `SOFR`, `€STR`;
   - сегменты: `Гос`, `Корп`, `Секьюритизация`.
9. **Погашенное не удалять.** Бумаги и сделки, которые жили хотя бы один день за год, должны остаться в справочниках: на них ссылаются исторические срезы.
10. **Пропуски.** Нет данных за день — не заполнять предыдущим значением. Лучше пропуск: `/api/v1/coverage` покажет дыры, а исторические сценарии пропустят неполные окна.

## 3. Как загружать

```bat
python -m tdm load C:\tdm_data\
```

- `load` — загрузить все `*.csv` из папки и подпапок;
- имя файла определяет набор: `positions_2026-10-13.csv`, `md_fx_2025.csv`, `instruments.csv`;
- справочники грузятся раньше срезов автоматически;
- разделитель `;` или `,`, десятичная запятая допустима при `;`, кодировка UTF-8 или cp1251 — то есть можно сохранять прямо из Excel.

Каждый файл грузится одной транзакцией. Если хоть одна строка с ошибкой, файл не загружается, а в отчёте указаны номера строк и причины. Повторная загрузка того же файла безопасна: строки обновляются.

Проверить, что загружено:
- `python -m tdm coverage --from 2025-10-13 --to 2026-10-13` — какие наборы есть на какие даты;
- в браузере: `http://<сервер>:8080/api/v1/coverage`.

**Порядок первичной загрузки**
1. Справочники: `books`, `issuers`, `issuer_ratings`, `counterparties`, `curves`, `instruments`, `bond_cashflows`, `otc_deals`, `calendar`.
2. Рынок за год: `md_curves`, `md_fx`, `md_fixings`, `md_bond_quotes`, `md_cds`.
3. Срезы за год: `positions`, `funding`, `trades`, `pnl_official`.
4. `python -m tdm build-hist-scenarios` — исторические сценарии из рядов (`docs/SCENARIOS.md`).
5. Результаты расчётов: прогоны расчётного сервиса — за сегодня обязательно, за прошлые дни по возможности. Иначе загрузите `desk_history`.

**Ежедневно после закрытия**: `positions`, `funding`, `trades`, `md_*` и `pnl_official` за день → `python -m tdm load`, затем EOD-прогон расчётного сервиса.

<a id="books"></a>
### 1. Книги и деск — `books.csv`

- **Зачем:** Фильтры «Деск» и «Книги», группировки, привязка позиций и фондирования.
- **Приоритет:** обязательно. **Глубина:** текущая версия; обновлять при изменениях.
- **Где брать:** внутренний справочник книг / фронт-система.
- **Как грузится:** справочник (актуальная версия, upsert по ключу); ключ `book_id` → таблица `ref_book`. Шаблон: `contract/csv/books.csv`.

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|:-:|---|---|
| `book_id` | текст | ● | код книги, стабильный | OFZ |
| `name` | текст | ● | название для экрана | ОФЗ |
| `desk` | текст | ● | деск (Rates, Credit, FX Credit, FX, …) | Rates |
| `trader` | текст |  | ответственный трейдер | А. Иванов |
| `active` | 1/0 |  | книга используется (по умолчанию 1) | 1 |
| `ord` | целое |  | порядок на экране | 1 |

<a id="issuers"></a>
### 2. Эмитенты и группы — `issuers.csv`

- **Зачем:** Концентрации по группам связанных заёмщиков, секторы, сегмент «Гос», референсы CDS.
- **Приоритет:** обязательно. **Глубина:** текущая версия.
- **Где брать:** справочник контрагентов / кредитный риск / Cbonds / МосБиржа.
- **Как грузится:** справочник (актуальная версия, upsert по ключу); ключ `issuer_id` → таблица `ref_issuer`. Шаблон: `contract/csv/issuers.csv`.

| Поле | Тип | Обяз. | Описание | Пример |
|---|---|:-:|---|---|
| `issuer_id` | текст | ● | код эмитента (ИНН, LEI или внутренний) | 7710168360 |
| `name` | текст | ● | краткое название для экрана | Минфин РФ |
