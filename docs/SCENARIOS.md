# Сценарии: где и как считать

> **16.10.2026:** уровни 1–3 уточнены в [architecture/03_CALCULATION_SPLIT.md](architecture/03_CALCULATION_SPLIT.md) (T1/T2/T3, ADR-005): числа браузера только для отображения, точный пересчёт — задача бэкенда, кэрри переезжает в бэкенд.

Короткий ответ — **гибрид из трёх уровней**:
- **лёгкие расчёты по грекам — в самом мониторе**, мгновенно и для любого сценария;
- **полная переоценка стандартных и исторических сценариев — заранее**, в ночном батче расчётного сервиса;
- **полная переоценка произвольного сценария по запросу** — позже и только если окажется нужной.

Сервис данных (`tdm`) сам ничего не переоценивает. Он хранит определения сценариев, строит исторические шоки из рыночных рядов и раздаёт результаты, посчитанные расчётным сервисом.

---

## 1. Три уровня

| | Уровень 1. Чувствительности | Уровень 2. Полная переоценка заранее | Уровень 3. Полная переоценка по запросу |
|---|---|---|---|
| **Где** | браузер (`prototypes/desk-util.js → runScenario`) | расчётный сервис (ваша либа) | расчётный сервис, асинхронно |
| **Когда** | мгновенно, на каждое движение ползунка | раз в день после EOD (или после интрадей-прогона) | по кнопке, ответ через минуты |
| **Какие сценарии** | любые: пресеты, исторические, свои из конструктора | фиксированный список: пресеты и исторические | любой, который пользователь собрал в Scenario Lab |
| **Вход** | key-rate DV01, CS01, FX-дельта, матрица гамм (`position_gamma`) или выпуклость, спреды из прогона | позиции + рынок + шок | то же + определение шока |
| **Точность** | до второго порядка (гамма, выпуклость, кросс FX): 0,03–0,25 % MV при сдвиге доходности до ±500 б.п.; дальше — предупреждение | точная (сколько даёт либа) | точная |
| **Статус** | **работает** | **работает**: таблица `scenario_result`; монитор показывает её автоматически | **спроектирован** (таблица `scenario_job`, API ниже), не реализован |

Монитор сам выбирает источник. Если для пресета есть полная переоценка из `scenario_result` и пользователь не менял шок в редакторе, показывается она с пометкой «Полная переоценка (расчётный сервис)». Иначе — расчёт по чувствительностям с пометкой «Оценка по чувствительностям».

## 2. Уровень 1 — по грекам в мониторе (до второго порядка)

### Формулы (как реализовано в `runScenario`, `prototypes/desk-util.js`)

Для позиции *p* и шока *S*:
- Δr — сдвиг пилларов кривых, б.п.;
- Δs — сдвиг собственного спреда позиции, б.п.: кредитного у корпоратов и валютных бумаг, спреда ОФЗ к RUONIA у ОФЗ;
- Δx — изменение курса, %.

```
первый порядок
  rates     = Σ_кривые Σ_бакеты  DV01_p[c][i] × Δr[c][i]
  spread    = CS01_p × Δs        Δs = (_mult − 1)·spread_p + _all + rating[r] + sector[s] + issuer[i]   (кредит, аддитивно)
            + ofzSpr01_p × ofzSpread                                                     (ОФЗ: спред к RUONIA)
  fx        = Σ_ccy FXDelta_p[ccy] × FX[ccy] × Δx[ccy] / 100  + то же по телу фондирования самой бумаги (fxFunding)

второй порядок — «Выпуклость» (convexity)
  если у позиции есть матрица гамм (position_gamma, факторы IR / CS):
      Σ_a ½·Γ_aa·Δa² + Σ_{a<b} Γ_ab·Δa·Δb          — ставки×ставки, спред×спред, ставки×спред
  иначе, если есть выпуклость C к доходности:
      ½ · MV · C · ((Δy + Δs)·1e-4)²,   Δy = rates / DV01 — DV01-взвешенный сдвиг кривой
      (доходность = ставка + спред, поэтому кросс ставки×спред учтён автоматически)

кросс-эффект курса — «Кросс FX» (fxCross)
  если в матрице есть элементы с FX: Σ Γ_{FX,·}·Δx·Δ(·)
  иначе: (rates по кривым в иностранной валюте + spread валютной бумаги) × Δx / 100
  плюс выпуклость валютной части × Δx / 100
  (стоимость в RUB = курс × стоимость в валюте: переоценка по ставкам и спредам пересчитывается по новому курсу)

total = rates + spread + fx + convexity + fxCross
```

Плюс по книгам — FX-переоценка остатков ДС книг деривативов и РЕПО в валюте (`fundingFxByBook`). Тело фондирования облигации (в её валюте) переоценивается в `fx` самой бумаги, поэтому облигация на своём фондировании почти не даёт FX-PnL — так устроено фондирование в организации (`docs/ORG_CONVENTIONS.md` §2). Пропорционального разнесения фондирования книги (версия 1.2) больше нет.

Риск рублёвых облигаций — на кривой RUONIA; ОФЗ дополнительно несут спред ОФЗ к RUONIA (`ofzSpr01`), корпораты — CS01 к RUONIA. Базис КС − RUONIA — это разница шоков `RUB KEY` и `RUB RUONIA` (пресет «Базис КС − RUONIA +50»; в Scenario Lab — слайдер «Базис», при связанных кривых он сохраняется). Суверенные бумаги шокируются как все остальные: правило «Гос × 35 %» из прототипа удалено — методики спред-шоков у деска нет, правила задаются в сценарии.

### Точность: проверка против точной переоценки

`tests/js/scenario_engine.test.js` — 5-летняя облигация, купон 9 %, доходность 14 %; ошибка в % от MV:

| Шок | 1-й порядок | 2-й порядок |
|---|---|---|
| ставки +300, спреды +200 б.п. | 2,06 % | **0,19 %** |
| ставки −250 б.п. | 0,59 % | **0,03 %** |
| USD-бумага: ставки +150, спреды +300 б.п., рубль −30 % | 2,90 % | **0,18 %** |
| USD-бумага: ставки +400, спреды +100 б.п., рубль −20 % | 1,30 % | **0,23 %** |
| «2022»: ставки +900, спреды +400 б.п., рубль −35 % (сдвиг доходности 1300 б.п.) | 0,67 % | 4,0 % — **вне области точности** |

Второй порядок убирает 85–95 % ошибки первого. Матрица гамм и выпуклость на согласованных данных дают одно и то же: тест это проверяет.

**Граница: ±500 б.п. по доходности позиции.** Дальше остаток третьего порядка сравним с самой поправкой второго, и квадратичное приближение начинает переоценивать выпуклость: на «2022» оно хуже первого порядка. Поэтому монитор считает эффективный сдвиг доходности каждой позиции (Δy + Δs). Если он больше 500 б.п., результат помечается: «Шок N б.п. — нужна полная переоценка», с числом позиций и долей MV. Для таких сценариев нужен уровень 2.

### Где уровень 1 ошибается и с гаммами

| Ситуация | Почему | Что делать |
|---|---|---|
| Сдвиг доходности > 500 б.п. («2022») | третий и следующие порядки | полная переоценка (уровень 2); монитор предупреждает сам |
| Флоатеры с кэпами/флорами, бумаги с офертами | цена — не гладкая функция («ступенька» при включении опциона) | полная переоценка |
| ИЦБ / ABS | CPR зависит от ставок; гамма локальна | гамма помогает до ±100–200 б.п., дальше — полная переоценка |
| CDS при дефолте | jump-to-default не описывается производными | JTD (отдельная мера) |
| Позиции без гамм и без выпуклости (IRS, XCCY, CDS без матрицы) | второго порядка нет | передавайте матрицу `gamma` (`docs/DATA_CONTRACT.md` §4.3.3) |

### Какие вторые производные нужны (спецификация)

`position_gamma`, формат и методика — `docs/DATA_CONTRACT.md` §4.3.3. Факторы: `IR|кривая|бакет` (1 б.п.), `CS` (свой спред, 1 б.п.), `FX|валюта` (1 %).

Приоритеты:
1. **Ставки × ставки** — трёхдиагональная матрица по пилларам — для облигаций и свопов.
2. **Ставки × спред и спред × спред** — для облигаций и CDS.
3. **Курс × ставки и курс × спред.** Можно не давать: монитор посчитает их сам из DV01 и CS01.

Минимум — `convexity` у облигаций.

## 3. Уровень 2 — полная переоценка заранее

### Что считать

Все активные сценарии из `scenario_def`:
- **пресеты** (`kind = 'preset'`): КС+200, параллельные ±100, bull steepener, bear flattener, базис КС − RUONIA +50, спред ОФЗ +40, рубль −15 %, спреды ×2, стресс девелоперов и лизинга (по секторам), «2022»;
- **исторические** (`kind = 'historical'`, §4);
- около 15–20 сценариев в сумме.

### Когда

- **Вариант А (проще).** Внутри EOD-прогона, до публикации: `run.add_scenario_results(...)` в том же `with Run(...)`.
- **Вариант Б (быстрее показывает риски).** Сначала опубликовать прогон с рисками и PnL. Затем досчитать сценарии и приложить их к уже опубликованному прогону: `tdm.writer.attach_scenario_results(db, run_id, scenario_id, rows, funding_residual)`. Монитор подхватит результаты при следующем открытии страницы.

### Что выкладывать — `scenario_result`, по позициям

| Поле | Смысл |
|---|---|
| `rates` | эффект ставок |
| `spread` | эффект кредитных спредов |
| `fx_gross` | FX-переоценка самой позиции |
| `fx_funding` | FX-переоценка тела фондирования самой бумаги |
| `convexity` | второй порядок и прочая нелинейность по ставкам и спредам |
| `fx_cross` | кросс-эффект курса: переоценка валютной части по шокированному курсу |
| `total` | полная переоценка: PV(шок) − PV(база) |

Плюс `scenario_funding_result` — FX-переоценка остатков ДС и РЕПО по книгам.

Можно выкладывать только `total`: монитор покажет итог, но без разбивки по факторам. Методика разложения на компоненты — ваша. Например, последовательно включать факторы или считать каждый фактор отдельно, а остаток относить в `convexity`.

### Стоимость

Порядок величины:
- 100 позиций × 20 сценариев = 2 000 переоценок — секунды;
- 10 000 позиций × 20 сценариев = 200 000 — минуты.

Ночной батч справляется с запасом.

## 4. Исторические сценарии: строит `tdm` из рядов

```bat
python -m tdm build-hist-scenarios --horizon 1 10 --top 5
```

- `--horizon 1 10` — окна длиной 1 и 10 рабочих дней;
- `--top 5` — пять худших окон каждой длины;
- `--from` / `--to` — ограничить период (по умолчанию весь загруженный год).

### Шок окна (d₀ → d₁)

Считается из загруженных рядов (`docs/DATA_REQUIREMENTS.md`, уровень B):

| Фактор | Шок | Откуда |
|---|---|---|
| Кривые | ставка(d₁) − ставка(d₀) на каждом из 11 пилларов, б.п. | `md_curves` (узлы интерполируются на пилларсы) |
| Курсы | курс(d₁) / курс(d₀) − 1, % | `md_fx` |
| Спреды | медиана изменения спреда эмитентов по каждой рейтинговой корзине, б.п. (без суверена; рейтинг — на d₁) | `md_bond_quotes` (Z- или G-спред) + `issuer_ratings` |

### Какие окна берутся

Все окна за год переоцениваются по уровню 1 на **текущем** портфеле (чувствительности последнего опубликованного прогона), **с учётом второго порядка**: матрица гамм агрегируется по факторам, свой спред позиции относится к корзине её рейтинга; позиции без матрицы учитываются через выпуклость, кросс FX — из DV01 и CS01. Формулы те же, что в мониторе.
- Берутся `top` худших, без пересечения окон.
- Если прогона ещё нет, окна ранжируются по величине движения рублёвых кривых.

### Результат

- Сценарии `hist1d-2026-03-15`, `hist10d-…` записываются в `scenario_def` с `kind='historical'` и описанием окна. Монитор сразу показывает их наравне с пресетами (уровень 1).
- Расчётный сервис при желании досчитывает их полной переоценкой (уровень 2) — так же, как пресеты.
- Пересобирать стоит **раз в день** после EOD-прогона: портфель меняется, меняются и худшие для него окна. Добавьте `build-hist-scenarios` в ежедневный сценарий после загрузки и публикации.

### Ограничение

Год истории даёт окна только из этого года. Для стресса масштаба 2022 нужны ряды того периода — их можно загрузить дополнительно, и `build-hist-scenarios --from 2022-02-01 --to 2022-04-30` найдёт худшие окна. Сейчас «2022» задан вручную как пресет `stress22`.

## 5. Уровень 3 — по запросу (спроектирован, не реализован)

Нужен, если трейдеры станут регулярно собирать в Scenario Lab нестандартные стрессы и захотят точную, а не оценочную цифру.

```
Scenario Lab ──POST /api/v1/scenario-jobs {base_run_id, definition}──► tdm: scenario_job (queued)
                                                                              │
расчётный сервис (воркер): опрашивает очередь ◄───────────────────────────────┘
   claim → running → переоценка базового прогона под шок
   → scenario_def (kind='adhoc', id='job-<N>') + scenario_result для base_run_id → done
Scenario Lab ──GET /api/v1/scenario-jobs/<N>──► status: done → показывает результат «Полная переоценка»
```

Таблица `scenario_job` уже есть в схеме: `job_id`, `definition_json`, `base_run_id`, `status`, `requested_by`, время, ошибка, `result_scenario_id`.

Для реализации понадобятся:
- запись через API — сервер сейчас только читает;
- функции воркера `claim` / `complete` в `tdm.writer`;
- кнопка «Посчитать точно» в Scenario Lab.

Кэш по хешу определения шока: одинаковые запросы на один прогон не пересчитываются.

## 6. Сводка: какой сценарий где считается

| Сценарий | Определение | Оценка в мониторе | Полная переоценка |
|---|---|---|---|
| Пресеты (КС+200, ±100, steepener, рубль −15 %, спреды ×2, «2022») | `scenario_def`, `kind=preset` (`upsert_scenarios`) | всегда (уровень 1) | ночной батч (уровень 2), показывается автоматически |
| Исторические 1Д / 10Д | `build-hist-scenarios` из `md_*` | всегда | по желанию, ночной батч |
| Свой шок в Scenario Lab | в браузере (сохраняется локально у пользователя) | всегда | уровень 3, когда будет реализован |
| Обратный стресс («какой сдвиг даёт −1 млрд») | в браузере | уровень 1 (Scenario Lab, «Обратный разбор») | не нужен |
| Сценарии кэрри и фондирования (§7) | `carry_scenario_def` + график заседаний ЦБ; свои — в Scenario Lab | всегда (`runCarry`) | не нужна: это начисления, не переоценка |

### Какие данные нужны для сценариев

- **Уровень 1:**
  - **из прогона:** key-rate DV01 (`position_risk`), CS01, FX-дельта, **вторые производные** (`position_gamma` или `convexity`), спреды и рейтинги (`docs/DATA_CONTRACT.md`);
  - **из входного слоя, для исторических шоков:** ряды кривых, курсов и котировок облигаций, история рейтингов (`docs/DATA_REQUIREMENTS.md`).
- **Уровни 2–3:** всё, что нужно либе для переоценки:
  - условия бумаг и сделок (`instruments`, `bond_cashflows`, `otc_deals`);
  - позиции;
  - рынок на дату;
  - функция «переоценить под шок» в самой либе.

## 7. Сценарии кэрри и фондирования

Вопрос деска: **сколько кэрри я заработаю на горизонте при таком сценарии фондирования.**
- Где смотреть: Desk Monitor → «Фондирование» (матрица сценарии × горизонты, разбор по книгам) и Scenario Lab → «Кэрри и фондирование» (конструктор).
- Расчёт — `runCarry` в `prototypes/desk-util.js`, в браузере, мгновенно. Тесты — `tests/js/funding_carry.test.js`.

### Допущения

- **Позиции постоянны**: MV бумаг, тела фондирования, остатки ДС и номиналы деривативов не меняются, курсы — сегодняшние.
- **Погашения и оферты учтены.** Бумага выбывает в `yield_date` (оферта), иначе в `maturity`. После этого у неё нет ни дохода, ни фондирования: денежные потоки уходят казначейству.
- Шаг — **календарный день**; начисление дня t — по ставкам, действующим в день t (выходные — по ставке пятницы).

### Компоненты

| Компонента | Формула за день t |
|---|---|
| `income` | облигации: грязная MV, RUB × y(t) / 365. Фикс. — y = доходность; флоатер — y = доходность + (индекс(t) − индекс сегодня). HTM — цена покупки × доходность покупки |
| `funding` | строки `POS` / `HTM`: тело × курс ЦБ × ставка(t) / 365. `POS`: индекс(t) + спред (+ сдвиг спреда сценария) или фикс. (hard ccy — ставка сценария); `HTM` — контрактная, не меняется |
| `derivs` | IRS: ± номинал × (плавающий индекс(t) − фикс) / 365; CDS: ∓ номинал × running-купон / 365; XCCY — сегодняшний кэрри, постоянно |
| `cash` | строки `CASH` / `REPO`: тело × курс × O/N(t) / база |
| `rolldown` | по желанию, к горизонту h: Σ по кривым риска DV01 × (r(T − h) − r(T)), б.п.; фикс. облигации и IRS, живые на горизонте. На промежуточных точках — линейно |
| `net` | сумма |

### Индексы в сценарии

| Индекс | Траектория |
|---|---|
| `КС` | по сценарию (ниже) |
| `RUONIA`, `RUSFAR O/N` | КС(t) + сегодняшний базис к КС + сдвиг `on[индекс]` |
| `RUSFAR CNY`, `SOFR`, `€STR`, `SARON` | сегодня + сдвиг `on[индекс]` |

### Траектория КС — `ks.mode`

| Режим | Что делает |
|---|---|
| `flat` | КС не меняется — база для сравнения («Δ к КС без изменений») |
| `implied` | на каждом заседании — средний форвард кривой `RUB KEY` до следующего заседания, шаг 0,25 п.п. |
| `steps` | шаг на каждом заседании, б.п. (`steps[i]` для i-го заседания после `as_of`) |
| `path` | явная траектория `[{date, ks}]` |

Новая КС действует со следующего рабочего дня после заседания. График заседаний — набор `cbr_meetings`; в прототипе он ориентировочный.

### Пресеты (временные, деск поправит)

КС без изменений · рынок (форварды RUB KEY) · −100 б.п. на каждом заседании · 3 × −200 б.п. и пауза · +200 б.п. и пауза · спред фондирования +50 б.п. · RUSFAR CNY +300 б.п. · hard ccy 7 %. Горизонты: 1M, 3M, 6M, 1Y и любая дата.

### Чего нет (пока)

- Реинвестирования погашений и новых сделок — портфель «замораживается».
- Изменения MV во времени (pull-to-par в балансе фондирования, переоценка по ставкам).
- Лага фиксинга у ОФЗ-ПК и у свопов, кэпов и флоров.
- Изменения курсов.
- Истории ставок фондирования: используется текущий справочник.
