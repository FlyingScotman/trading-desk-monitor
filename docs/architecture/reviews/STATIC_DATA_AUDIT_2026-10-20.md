# Аудит справочника облигаций (market static), 20.10.2026

Запрос владельца R9: «У эмитентов и выпусков нет рейтингов, отраслей и т. п.; у части облигаций нет купона в описании; облигация „Газпром нефти“ почему-то называется SIBN … Выгрузить набор бумаг без позиций, критически проверить, сформировать задачи для модуля маркет-статик данных». Задачи для хаба: [`briefs/HUB_STATIC_DATA_REQUESTS.md`](../briefs/HUB_STATIC_DATA_REQUESTS.md).

## Кратко для владельца

1. **Рейтингов нет нигде: ни в хабе, ни в контракте.** В хабе есть пустая таблица `ref.bond_rating` (0 строк), её мог бы заполнить только Cbonds, а доступ к Cbonds отклоняется (HTTP 401, задача хаба WEB-8). В контракте снапшота поля рейтинга нет, поэтому монитор всегда показывает пустой рейтинг. MOEX публикует рейтинги в ISS (`/iss/cci/rating/...`), но только по подписке: без неё ответ «Информация доступна только подписчикам» (проверено 20.10).
2. **Отрасли, краткого наименования эмитента, ОГРН и страны нет у 100 % эмитентов.** Поля `sector`, `short_name`, `ogrn`, `country` есть в контракте, но загрузчик хаба их не заполняет. Публичный ISS `/iss/emitters/{id}` отдаёт краткое наименование (100 % выборки из 80 эмитентов), ОГРН (95 %) и страну (100 %). Отрасли в публичном ISS нет: отраслевые коды MOEX (CCI) тоже доступны только по подписке.
3. **Группы эмитентов нет.** Монитор подставляет в «группу» полное юридическое наименование эмитента, поэтому «Газпром», «Газпром капитал» и «Газпром нефть» — три разные группы. Строковое сопоставление тоже не работает: «Газпромбанк» — не группа «Газпром», а СФО «ВТБ РКС» — секьюритизация, а не долг ВТБ. Нужен ведомый (curated) справочник групп в хабе.
4. **«Нет купона» — в основном флоатеры.** Из 2 204 активных облигаций, которые ядро может оценить по статике, монитор не покажет купон у 436. Из них 417 — флоатеры: 73 % всех оцениваемых флоатеров. У текущего периода флоатера MOEX публикует сумму, но не ставку, или ничего не публикует. Монитор берёт только ставку и формулу (индекс + маржа) не показывает: поля `index`/`margin` позиции не заполняются никогда. Пример: у «Газпром нефти» 24 выпуска, и купон будет показан только у трёх.
5. **«SIBN …» — это имя из банковского отчёта, а не из справочника.** SIBN — биржевой код акций «Газпром нефти» (бывшая «Сибнефть»). В справочнике хаба все облигации «Газпром нефти» названы по MOEX («Газпнф3P8R», «ГПН005Р-12», полное «Газпром нефть БО 003P-08R»), и строки «SIBN» в хабе и деске нет. Монитор показывает имя из отчёта (`Name` → `source_instrument_name`), когда позицию **не удалось сопоставить** со снапшотом по ISIN. Тогда класс актива — «Не сопоставлено», эмитент — «Не сопоставлено», купона и риска нет. Вероятная причина несопоставления: снапшот содержит только торгуемые (`active`) и недавно погашенные выпуски. **1 224 непогашенных, но неторгуемых выпуска (`delisted`) в снапшот не попадают**, среди них пять облигаций «Газпром нефти» БО-01…БО-07 с погашением в 2046 г. (RU000A0JWRE5 и др.). Чтобы подтвердить причину, нужен ISIN позиции «SIBN …» из отчёта.
6. **Ядро может оценить по статике 81 % «наших» бумаг.** Из 4 029 активных облигаций 1 321 — структурные ноты (Сбер КИБ, ВТБ, Альфа; не продукт деска). Из остальных 2 708 проходят проверки 2 204. Не проходят: 270 с валютным номиналом (USD/CNY/EUR/CHF, пакет ядра 3), 175 ипотечных и секьюритизаций, 38 флоатеров на неподдерживаемых индексах (КБД, ИПЦ, RUONIA 6M), 18 с индексируемым номиналом, 7 с неполным графиком погашений и 6 с неизвестным купоном.
7. **Класс бумаги (`bond_class`) в целом верен.** ОФЗ, субфедеральные, муниципальные, структурные, ипотечные и валютные суверенные выпуски распознаются корректно. Слабые места: класс «corporate» (2 366 выпусков) — это всё остальное, без разметки квазигоса, банков и лизинга, а признак `is_quasi` в мониторе всегда false. У 579 выпусков тип купона `unknown`: 464 структурные, 98 амортизируемых с постоянной ставкой (пример: ТомОб34079, 16,4 % каждый месяц).
8. **Названия бумаг в мониторе — MOEX SHORTNAME (до 10 символов):** «Газпн3P15R», «iСелкт1Р10», «NSKATD-03». В данных есть читаемое полное имя «Газпром нефть БО 003P-15R» (MOEX NAME), и в хабе лежит латинское «Gazprom Neft 003P-15R» (`lat_name`, не опубликовано). Эмитент показывается полным юридическим наименованием в регистре MOEX: «открытое акционерное общество "Российские железные дороги"» (71 выпуск РЖД), «АКЦИОНЕРНОЕ ОБЩЕСТВО "АЛЬФА-БАНК"».

**Что сделано:** команда `desk instruments export` (выгрузка справочника из кэша снапшотов, без позиций, с флагами качества и причинами), полная выгрузка вселенной MOEX на 20.10.2026 и этот отчёт.

## Как получена вселенная

Использован **код самого хаба** (market-data-hub, commit `4e254b0`) против публичного MOEX ISS. Копия репозитория хаба была развёрнута во временном каталоге, с одноразовым PostgreSQL 16 (pgserver), без секретов. Запущенные задания:
- `bonds_static` — дважды; второй прогон уже с историей ключевой ставки, без которой правило `schedule_constant` не срабатывает;
- `cbr_daily` с 2019-01-01;
- `cbr_meetings mode=calendar_full` (календари);
- `bonds_eod`, `zcyc`, `fx_moex_eod`, `indices_eod` за 19.10.2026;
- `snapshot_static` за 20.10.2026 и `snapshot_market eod_final` за 19.10.2026.

Получились настоящие снапшоты контракта v1:
- static `2d00b9dfa953…` (4 192 инструмента);
- market `82533c2cf5e1…` (8 MB распакованный).

Они прошли через адаптер деска (`marketdata/adapter.py` → `BondTerms`) и через проверки `valuation/bonds.py` (`fixed_schedule`: те же проверки, что у позиции до ядра). С флагом `--value` вся вселенная ещё оценена ядром по котировкам 19.10. Выгрузка: `desk instruments export --snapshots <папка> --date 2026-10-19 --value`.

**Отличия от продакшен-хаба:**
- Нет курируемых формул флоатеров из legacy-импорта: в продакшене их несколько, здесь все 642 формулы `inferred`/`partial`, как в фикстурах хаба.
- Нет Cbonds: в продакшене его тоже нет из-за 401.
- Нет кривых свопов (ratescalcs/OTC требуют токенов). Поэтому в рыночной части 504 флоатера получили `core_missing_market_data`. Это артефакт среды, а не справочника.

## Находки по степени влияния на деск

### F1. Рейтингов нет; отраслей, групп и кратких имён эмитентов нет (влияет на все кредитные отчёты и концентрации)

- `issuers` снапшота: 536 эмитентов активных бумаг. `short_name`, `ogrn`, `sector`, `country` пусты у всех. Загрузчик `bonds_static._issuer_rows` пишет только `name`, `inn`, `okpo` из справочника `/securities.json`.
- Рейтингов в контракте нет. `ref.bond_rating` пуст: единственный источник — Cbonds (`get_rating_emission_maxdate`), он отклонён.
- В мониторе (`publish/tdm_run._issuer_key`, `api/compat.py`):
  - `issuer` = краткое имя эмитента, а при его отсутствии — полное, то есть всегда полное;
  - `issuer_group` = полное имя;
  - `sector` = `issuers.sector` (null);
  - `rating` = None константой;
  - `is_quasi` = False константой.
- Что реально доступно:
  - **ISS `/iss/emitters/{id}`** (публично, проверено): SHORT_TITLE, OGRN, OKSM (страна), TITLE, INN. Пример 1039: «ПАО "Газпром нефть"», 1025501701686, 643. Выборка 80 эмитентов: SHORT_TITLE 80, OGRN 76, OKSM 80. Список `/iss/emitters.json` отдаёт TITLE/INN/SHORT_TITLE постранично (1 354 записи).
  - **Отрасль:**
    - MOEX CCI (`/iss/cci/info/companies/industry-codes`, `/iss/cci/reference/industry-codes`) — только по подписке.
    - ОКВЭД по ИНН — ФНС: ЕГРЮЛ (egrul.nalog.ru) и ГИР БО (bo.nalog.ru, в JSON карточки организации есть ОКВЭД2). Это публичные источники, но из этой среды они закрыты политикой исходящего трафика, поэтому не проверены. Ожидаемый путь: ОКВЭД (факт) → отраслевая таксономия деска (курируемая таблица соответствия), плюс ручные исключения для СФО, ипотечных агентов и «…капитал» (отрасль оригинатора).
  - **Рейтинги:**
    - Cbonds — лицензия; загрузчик уже есть, блокер — доступ API (WEB-8).
    - MOEX CCI `/iss/cci/rating/{companies|securities}` — подписка. Стоит проверить, покрывают ли её действующие APIM-реквизиты хаба.
    - Сайты АКРА, Эксперт РА, НКР, НРА публикуют действующие рейтинги, у части есть выгрузки в Excel. Это реально, но это четыре парсера и вопрос лицензии на перепубликацию; из этой среды сайты закрыты (403 прокси).
  - **Группы:** публичного машиночитаемого источника нет: СПАРК/Cbonds — платные, ЕГРЮЛ не раскрывает акционеров ПАО. Реально — курируемый файл групп в хабе, по образцу `mdhub/data/calendar_curated.json`.
- Примеры, почему группы нельзя выводить из названия:
  - эмитенты со словом «Газпром»: «Газпром», «Газпром капитал» (SPV Газпрома), «Газпром нефть» (дочерняя Газпрома) — одна группа; «Газпромбанк» — другая;
  - «ВТБ»: «Банк ВТБ», «ВТБ Лизинг», «ВТБ Факторинг», «VTB Capital S.A.» — группа ВТБ; три «СФО ВТБ РКС …» — секьюритизация с другим кредитным риском;
  - «Сбер»: «Сбербанк России» и «Сбербанк КИБ» (561 структурная нота).

### F2. Позиции, не сопоставленные со справочником, показываются под банковским именем («SIBN …»)

- Цепочка:
  1. Адаптер (`trades-data-adapter`, `positions_daily.py`) кладёт колонку отчёта `Name` в `source_instrument_name` и ищет `instrument_id` по ISIN (`ctx.instruments.lookup("isin", …)`).
  2. Бэкенд (`valuation/positions._resolve`) ищет ISIN/regnum/SECID среди `instruments` статического снапшота.
  3. Если не нашёл — ступень `reported_value`, и `publish/tdm_run.direct_row` пишет `name` = `source_instrument_name`, `asset_class` и эмитент = «Не сопоставлено», купон и риск пусты.
- Справочник хаба не содержит строки «SIBN» ни в одном поле: SIBN — код акции на `/iss/emitters/1039/securities`, хаб его не загружает. Значит, «SIBN …» — название из банковской системы для несопоставленной бумаги.
- Почему бумага может не сопоставиться:
  - **(a) Не в снапшоте.** Вселенная static = `active` + погашенные за 31 день. **1 224 непогашенных выпуска со статусом `delisted`** (нет на торгах) исключены:
    - corporate 1 001, из них 473 — не структурные ноты; mbs 115, subfederal 37, cbr_bond 21;
    - примеры: «Газпром нефть» БО-01…БО-07 (RU000A0JWRE5, RU000A0JWRF2, RU000A0JWK41, RU000A0JWB67, RU000A0JWB75; погашение 2046, `is_traded` = 0), ГазпромБ22/23 (2048), ВТБ 5ИПА/5ИПБ (2046), НКК БО-01/02 (2050).
    - Бумаги, выкупленные на оферте, внебиржевые и неразмещённые остатки бывают на балансе банка.
  - **(b) ISIN не на MOEX:** еврооблигация без замещающего выпуска или локальный код.
  - **(c) ISIN неоднозначен** (`isin_shared_with`): таких в активной вселенной нет.
  - **(d) Устаревший индекс инструментов адаптера:** `index.json` строится из последнего static кэша. Новые выпуски («ГПН005Р-13», размещён в октябре) видны только после синхронизации.
- Проверка у владельца:
  - `desk instruments export --out x.csv` и поиск ISIN позиции «SIBN …» в выгрузке;
  - если его нет — смотреть ISIN в https://iss.moex.com/iss/securities/<ISIN>.json и статус `is_traded`.
- Исправления: хабу — HS2 (опубликовать delisted-непогашенные), деску — D6.

### F3. Купон в мониторе пуст у ~3/4 флоатеров и у бумаг, которые ядро не оценивает

- Флоатеры, которые ядро оценивает: 574. Купон показан у 157, **пуст у 417**.
- Статусы текущего периода флоатеров по хабу:
  - `unknown` 346 — в периоде нет ни суммы, ни ставки: MOEX не публикует купон в арреарс до фиксации;
  - `current_published` 233 — есть сумма, ставки нет у части;
  - `projected_by_moex` 40;
  - `known` 22.
- Ставка есть у 219, сумма — у 295.
- Монитор берёт `current_coupon_pct` = ставка первого купона после даты оценки. Для флоатера ставок нет (`_fill_coupons` оставляет их как есть), поэтому купон пуст. Поля `index` и `margin` позиции API ждёт (`compat.py`: `p.get("index_name")`, `p.get("margin")`), но `position_row` их не пишет никогда.
- Прочие пустые купоны среди оцениваемых: 15 «депозитных» нот Сбера (`unknown`, график пуст), 2 `variable_known`, 2 `zero`.
- Не оцениваемые ядром бумаги — валютные (270), ОФЗ-ИН/ИН-номинал (18), ипотечные (175) — уходят на запасную ступень. Там `current_coupon_pct` = None, хотя ставка в статике есть (sovereign_fx 100 %, mbs 70 %).
- Исправление на стороне деска (D4):
  - показывать ставку из статики для любой бумаги;
  - для флоатера — опубликованную сумму в пересчёте на ставку, иначе проекцию «индекс + маржа» с пометкой;
  - заполнять `index`/`margin` из формулы.

### F4. Тип купона и частота: где хаб не знает, а где знает, но монитор теряет

- `unknown` — 579 активных:
  - 464 структурные — допустимо;
  - **98 «Амортизируемая облигация» без COUPON_DETAILS** при постоянной положительной ставке: ТомОб34079 RU000A10GBM8 (16,4 % ежемесячно), Новосиб 24, Брус 2P02. Правило хаба `schedule_constant` требует двух выплаченных купонов, между которыми было изменение КС, поэтому новые выпуски остаются `unknown`.
  - На оценку это не влияет: `unknown` проходит, будущие купоны берутся по последней ставке с пометкой.
- `variable_known` — 429:
  - 298 по метке MOEX «фиксированный с неизвестными купонами»;
  - 131 по графику, из них 46 с меткой «известные купоны», но с пустыми будущими периодами (МЕТИН2P03: 50 купонов без значения).
- Монитор показывает тип купона только как `fix`/`float`: `zero`, `indexed_face`, `variable_known` и `unknown` отображаются как «fix» (D5).
- `coupon_frequency` пуст у 876 (структурные 776, корпоративные 95, субфедеральные 4). MOEX не публикует COUPONFREQUENCY, если первый период неравный (РЖД 1Р-20R). Частота по графику вычисляется всегда (`implied_frequency` в выгрузке). Расхождение с MOEX есть только у 2 бумаг.

### F6. Наименования бумаг и эмитентов в мониторе нечитаемы

- Позиция называется `short_name or name`, то есть MOEX SHORTNAME. Длина ≤ 10 символов у всех; у 3 110 из 4 029 ровно 10, это предел MOEX.
- Отсюда «Газпн3P15R», «ГПН005Р-12» (у одного эмитента две схемы сокращения), «iСЛ 2P3» (35 выпусков с префиксом `i` MOEX), «NSKATD-03» (123 латиницей).
- Полное MOEX NAME читаемо («Газпром нефть БО 003P-15R», «Софтлайн 002Р-03»). Это `name` в снапшоте, монитор его не использует. В хабе есть `lat_name` («Gazprom Neft 003P-15R»), в контракт он не выведен.
- Эмитент показывается полным юридическим наименованием в виде, в каком его хранит MOEX: прописные («АКЦИОНЕРНОЕ ОБЩЕСТВО "АЛЬФА-БАНК"», 8 эмитентов), старая ОПФ (РЖД — «открытое акционерное общество», так и в `/iss/emitters/712`). Краткое имя MOEX («АО "АЛЬФА-БАНК"», «ОАО "РЖД"», «Банк ВТБ (ПАО)») исправило бы почти всё (HS1), а ведомое отображаемое имя группы — остальное (HS4).

### F7. Оферты, погашения, номинал

- 588 оферт без даты (`date_missing`) у 587 корпоративных бумаг: MOEX-строки с пустой датой. При выборе горизонта деск их игнорирует. Если это реальные будущие пут-оферты, горизонт и доходность считаются неверно.
- 9 бумаг с подтипом «До оферты (put)» без запланированной оферты: Ростел1P3R, Совком БО5, Роснфт1P8, СолтонБО01.
- 7 бумаг `redemption_incomplete` — все с выплатой 20.10, в день снапшота: ИЛСБО-1-1Р, ЯрОбл 2017, АквилонЛP3.
  - Снапшот собран днём, и MOEX уже уменьшил FACEVALUE: ЯрОбл 2017 — номинал 125 при выплатах 125 сегодня и 125 в 2027.
  - Деск по правилу H25 считает номинал снапшота «до выплаты в его дату» и вычитает её ещё раз. На продакшен-снапшоте 07:45 правило могло выполняться, но это время сборки, а не контракт (HS11, D7).
  - У ИЛСБО-1-1Р данные MOEX противоречивы и сами по себе: номинал 400, выплаты 300 и 400.
- Суммы погашений ≠ номиналу:
  - 5 секьюритизаций (ТБ-4_А1);
  - ЗО-30 и RUS-30 (номинал 0,035 при выплатах 0,07 на «бумагу» с лотом-долей).

### F8. Класс бумаги

- `bond_class` выведен из меток MOEX и ИНН Минфина детерминированно. В проверенных срезах ошибок не найдено:
  - все 1 321 бумага с флагом MOEX STRUCTBOND — `structured`;
  - нет нот с «структурн» в имени вне `structured`;
  - ОФЗ по сериям верны;
  - `foreign_sovereign`: 16, из них 5 рублёвых — оцениваются.
- Недостатки — в таксономии, а не в ошибках:
  - `corporate` объединяет банки, лизинг, госкомпании, SPV и девелоперов (нужны отрасль и группа, F1);
  - нет признака квазисуверена: ВЭБ.РФ, РЖД, ДОМ.РФ — `corporate`, а `is_quasi` в мониторе всегда false.

## Что сделано в репозитории деска

## Technical notes

- Hub code mirrored/used:
  - `src/mdhub/loaders/bonds_static.py` (`build_bond_row`, `_issuer_rows`);
  - `src/mdhub/sources/moex_static.py` (`classify_bond`, `classify_coupon_type`, `schedule_constant_fixed`);
  - `src/mdhub/snapshot/static.py` (`_universe`: `status = 'active' OR (matured AND maturity >= business_date - 31)`);
  - `src/mdhub/snapshot/runner.py`.
  - Nothing was changed in the hub repository; a clone in a temp directory was used.
- Run log:
  - `bonds_static` run 1: 15 964 directory SECIDs, 11 775 collection, 3 484 market rows, 941 descriptions, 2 231 bondization pages, 16 066 bonds written;
  - run 4 repeated it with the key-rate history;
  - statuses in `ref.bond`: matured 10 774, active 4 029, delisted 1 263.
- Desk mapping: `StaticView` (adapter) → `BondTerms`. `core_static` is `valuation.bonds.fixed_schedule(terms, business_date)`: eligibility, face, maturity, redemptions, floater rule, coupon filling. Its `current_coupon_pct` is the coupon a position would show.
- Caveats:
  - The market part has no swap curves (no ratescalcs/OTC credentials), so the RUONIA and key-rate floaters fail with `core_missing_market_data` there. Their static eligibility is unaffected.
  - The static snapshot was built intraday on 20.10. Production builds at 07:45 MSK, which matters for F7 (same-day redemptions).
