# Static data requests to the market-data hub (R9)

As of 20 October 2026. From the desk (this repository) to `market-data-hub`.

Evidence comes from [the static data audit of 20.10.2026](../reviews/STATIC_DATA_AUDIT_2026-10-20.md), which ran the hub's own collectors (commit `4e254b0`) against public MOEX ISS and pushed the resulting snapshot through the desk's adapter and valuation checks. Items continue the list in [HUB.md](HUB.md): HS = hub static. Where an item restates an existing H-item, it says so.

## Contract versioning

The rules are those of the hub's `schemas/market_snapshot/v1/README.md`: every object has `additionalProperties: false`, so a new field or dataset is a schema version bump. The items fall into two groups.

- **Data-only, still `market_snapshot/1.0`.** HS1 fills `Issuer.short_name`, `ogrn` and `country`, which exist and are always null. HS2 publishes instruments with `status: "delisted"`; the enum already allows it, the new label `not_traded` is a free label, and `parameters.universe` changes value. HS3a fills `Issuer.sector`. These can ship now. The desk reads them without change.
- **Additive, `market_snapshot/1.1`.** This covers new fields on `Issuer` (`okved`, `group_id`, `group_name`, `group_relation`, `is_state_owned`), on `Instrument` (`lat_name`, `coupon_frequency_schedule`, `face_value_date`), and a new `ratings` dataset. Ship them together as one bump, with regenerated golden fixtures in a reviewed change (`MDHUB_REGEN_GOLDEN=1`). Update the interface catalogue in `docs/architecture/README.md` of this repository at the same time.

Desk item D10 has landed (20.10): the desk reads any `market_snapshot/1.x` and ignores unknown additive fields; it refuses another major. The hub may publish 1.1.

## How to re-check

From a desk cache: `desk instruments export --out instruments.xlsx [--date D] [--value]`. The summary sheet and the console print the fill rate per field, the core reasons and the flag counts. The acceptance numbers above are those counts.
