# Публикуемая ОВП «база отчёта + день» (TDM#531)

Решение владельца 03.11.2026 (FlyingScotman/trading-desk-monitor#531, комментарий «Решения владельца и схема»),
меняет OQ-18 ([DECISIONS](../program/DECISIONS.md)). Код: `backend/src/desk/rules/ocp.py` (`published_day`,
`carried_units`, `trade_flows`, `derivatives_check`), `backend/src/desk/publish/ocp_run.py` (`base_days`,
`bond_moves`, `paid_since`), блок `ocp` прогона v3, `/api/v1/runs/{id}/ocp`, `/api/v1/history/ocp`. Договор с
адаптером — `private/1.7` ([08 §10 `ocp`](08_PRIVATE_ADAPTER_INTERFACE.md)). Экран разбора цифры — отдельная задача
FlyingScotman/trading-desk-monitor#532.

## Зачем

Отчёт ОВП приходит утром за прошлый рабочий день, прогон идёт на сегодня. Прежний базис (`report_plus_outside`,
TDM#416) брал отчёт только своей даты, поэтому внутри дня ОВП почти всегда считалась из позиций. Будущие потоки
деривативов отчёт держит в номинале, а владелец хочет их PV. Новый базис берёт отчёт за прошлый рабочий день как
базу и прибавляет то, что изменилось с тех пор.

## Обозначения

- **D** — дата прогона, **t** — его время.
- **B** — дата базы: последний отчёт ОВП юрлица с датой ≤ D, не старше `report_max_age_bd` рабочих дней (по
  умолчанию 1: отчёт пятницы годен в понедельник). Рабочие дни — по календарю прогона (биржевой календарь ядра), вне
  его окна — будни. На прогоне за саму дату отчёта B = D.

ОВП считается в единицах валюты: курсы её не меняют. Меняют её только новые потоки и цены инструментов в валюте.

## Формула (юрлицо × книга × валюта)

```
ОВП(t) = база(B)                 отчёт ОВП на B без будущих потоков тех видов деривативов, которые отчёт даёт отдельно
       + деривативы(t)           PV позиций этих видов с потоком после B: FX-дельта ядра (эквивалент спот), при любом
                                 amount_basis; вида нет среди позиций книги — номинал из отчёта с пометкой
       + облигации(B → t)        грязная MV в валюте сейчас − на B + купоны и погашения, выплаченные в (B, t]
       + сделки после B          потоки сделок с датой сделки после B (набор trades, private/1.6)
       + вне отчёта              слагаемые, которых отчёт не держит (ocp_policy.report_components), из позиций
```

Слагаемые — `parts` строки (`base`, `derivatives`, `bonds`, `trades`, `outside`; у книги, которой нет в отчёте на B,
ещё `balances` — её остатки по счетам, DEC18), их сумма равна `amount`. У каждого
слагаемого — список вкладов (`contributions`): строка отчёта (набор `set_id`, файл, число строк), позиция, сделка; не
больше 10 самых крупных, остальное одной суммой (`rest`). Этого хватает экрану разбора (#532) и не раздувает прогон:
синтетический прогон с 1000 строк книга × валюта, у каждой три слагаемых с полным списком, — 4,0 МБ блока, а история
(`/api/v1/history/ocp`) отдаёт за такой день 0,3 МБ: вклады из базы она не читает.

Разбор строки на C16 (TDM#603) читает их из `/ocp` прогона дня. Для него у строки ещё `excluded`: по каждому виду,
который отчёт выносит, номинал, вынесенный из базы (`nominal`), против PV, добавленного из позиций (`added`; дериватив
вида вне отчёта — `outside`), и разница `diff`. Большая разница — признак типа строки отчёта, отнесённого к деривативам,
которого нет в позициях (спот, ближняя нога свопа): его ОВП пропадает. `derivative_types` — типы строк отчёта за этим
номиналом из поля адаптера `x_derivative_types` (строки отчёта `ocp`): тип, вид, вынесен (`kept` false) или оставлен в
базе по номиналу как спот (`kept` true), число строк и сумма; нет поля — список пуст. У сделки после базы в
`contributions.trades` — `asset` (тип) и `value_date` (валютирование).

### Виды деривативов (`private/1.7`)

Адаптер относит типы строк отчёта к видам деривативов, монитор — свои позиции:

| Вид | Что | Слагаемое монитора (показ, сверка) |
|---|---|---|
| `fx_forward` | поставочный форвард, кросс не спот, FX-строка без условий со сроком после окна расчётов | `fx_legs` |
| `fx_swap` | валютный своп | `fx_legs` |
| `fx_future` | валютный фьючерс | `futures` |
| `ndf` | беспоставочный форвард | `ndf` |
| `fx_option` | валютный опцион | `options` |
| `swap` | IRS, OIS, CCS с валютной частью | `fx_legs` |
| `other` | любой другой дериватив | `other` |

Монитор определяет вид позиции по продукту ядра, группе продукта в отчёте и условиям сделки. **Спот** (дата
валютирования не позже даты сделки + `settle_window_bd` рабочих дней) деривативом не бывает. Акция, фонд, депозит,
облигация, РЕПО — тоже: такие строки (в том числе слагаемое `other` монитора) остаются в базе и в PV не входят.

### Правила

1. **База.** Для каждого вида, который адаптер сопоставил, он убирает из `ocp_ccy` строки этого вида с датой
   валютирования позже B и отдаёт их номинал в `derivatives_ccy[вид]`. Ключ есть, хоть со значением «0», — вид
   вынесен. Решение — **по файлу отчёта и виду**: ключ хоть у одной строки файла выносит вид для всех частей файла,
   в том числе для части без строк. База — `ocp_ccy` (`base_kind` `without_derivatives`, вынесенные виды —
   `split_kinds`). Вид, который не вынесен, остаётся в базе по номиналу и PV не получает. Значит, тип строки, не
   сопоставленный ни с каким видом, безопасен: двойного счёта нет. Адаптер до 1.7 поля не даёт: база держит все
   деривативы по номиналу, это сказано в пробелах (`report_without_derivatives_split`, `base_kind`
   `with_derivatives`).
2. **Отчёт — полный срез юрлица на B.** Книга юрлица без строк в отчёте на B имеет базу 0 (`book_absent`), к ней
   добавляются PV всех видов и изменения дня. Источник отчёта объявлен `covers: listed`, поэтому часть отчёта по
   книге, которая выпала из более позднего отчёта (книга закрыта, авто-книга, чей код теперь ведёт в другую книгу),
   остаётся «в силе» со старой датой. В базу такая часть **не входит**: B у юрлица одна — дата его самой новой части,
   части старше B дают книге 0, а не старую цифру. В пробелах — `carried_forward_unit`: «книга X: последняя строка
   отчёта от <дата>, в базу не входит». Сверка с отчётом их по-прежнему показывает.
3. **Деривативы.** Для каждого вынесенного вида — PV всех позиций этого вида с потоком после B (последняя дата потока
   > B: самая поздняя из дат ног, начала и погашения по условиям, срока строки; своп, начавшийся до B, поток после B
   имеет; дериватив, рассчитавшийся до B включительно, уже в базе; даты нет совсем — считается и названо в пробелах
   `derivatives_unknown_last_flow`). Вид позиции читается и из группы продукта отчёта (FX-своп без условий — `fx_swap`,
   не форвард). В слагаемое попадает позиция, чья строка ОВП — деривативное слагаемое, которое отчёт держит. Сделка
   переноса ОВП (`transfers`) и спот-нога свопа (`cash`) остаются в базе. Позиция, чья строка вне отчёта, считается
   во «вне отчёта» целиком и здесь не повторяется: оба слагаемых по позиции не пересекаются. Всегда PV: FX-дельта ядра, даже
   если `amount_basis` = `nominal` (он остаётся у сверки с номиналом отчёта). Поток дериватива с датой D входит в PV
   почти номиналом, поэтому дыры между «ещё дериватив» и «уже кэш» нет. Вид вынесен, а позиций этого вида в книге нет
   (нет условий сделки, ядро не оценило) — номинал отчёта с пометкой «номинал, PV нет» (`fallback`, пробел
   `derivatives_nominal_fallback`). Если позиции вида есть, но часть из них без PV (оценена по номиналу без условий
   или не оценена), номинал отчёта по позициям не делится. Поэтому досчитать долю неоценённых нельзя: берётся то, что
   есть (у позиций без PV — их номинал из отчёта позиций, вклад с пометкой «номинал позиции, PV нет»), а неполнота
   названа (`partial_pv` строки, пробел `derivatives_partial_pv`, `positions` / `without_pv` / `partial` в
   `derivatives_check`). Если PV нет ни у одной позиции вида (условия сделок не привязаны, ядро не оценило) — это
   тот же случай, что «позиций вида нет»: номинал отчёта по виду и валюте с пометкой «номинал, PV нет» (`fallback` и
   `no_pv`, пробел «PV нет ни у одной позиции: номинал отчёта»; решение владельца 03.11.2026: дериватив без PV — не
   тихий ноль и не номинал позиции, а номинал отчёта с пометкой). Номинала вида в этой валюте у отчёта нет — остаются
   номиналы позиций с пометкой.
   Номинал отчёта не возвращается и тогда, когда позиции вида считаются во «вне отчёта» (например, перенос ОВП при
   `transfers` вне отчёта). NDF при `include_ndf` = false номиналом не возвращается. Вид, чьё слагаемое
   отчёт не держит (например, опционы), идёт через «вне отчёта».
4. **Облигации.** Та же формула, что у валютного пассива облигаций с прошлого переноса (`publish.fx_liability`): MV
   на B — из основного прогона за B (`run_position.fact.mv`), сейчас — из прогона. Выплаты в (B, t] — по графику
   бумаги: купон и погашение или амортизация на каждую дату выплаты × количество в этот день (на B плюс купленное и
   минус проданное сделками позиции до даты выплаты). Без условий бумаги — купоны дня валютного пассива, если его
   последний перенос — B, с пометкой «погашения не учтены». Позиция, которой на B не было, входит своей MV;
   проданная или погашенная — минус MV на B. Прогона за B нет — слагаемого нет, пробел `no_base_run`.
5. **Сделки после B.** Живые сделки наборов `trades` всех дат (B, D] с датой сделки после B: сделка за B или раньше
   (в том числе поздняя проводка) уже в отчёте на B. Одна версия на сделку — с наибольшим `trade_version`, при равных
   — из более позднего файла.
   - Валютная сделка — купленная (+) или проданная (−) валюта `amount_ccy`; со сроком дольше окна расчётов —
     номинал (PV при заключении). Если позиции книги датированы не раньше сделки и держат её как дериватив, сделка не
     считается, когда весь PV позиции уже учтён: вид вынесен, строка позиции вне отчёта (например, NDF вне отчёта) или
     позиция новая с B (её нет в прогоне за B или все сделки по её условиям после B — тогда её PV добавляется, даже
     если вид не вынесен). Позиция, которая была и до B (FX-позиция ключуется книгой, валютой и датой валютирования,
     строка ядра собирает несколько сделок), держит в базе старую часть по номиналу, поэтому сделка после B считается
     своим номиналом.
   - Облигация — оплата или выручка (∓`amount_ccy` ∓ `accrued_ccy`) и сама бумага по цене сделки, пока позиции книги
     датированы раньше сделки и прогон сделку в строку не внёс. Если позиции уже после сделки, бумага — в переоценке
     облигаций (проданная целиком — минус MV на B там, а не второй раз здесь).
   - **Сделка, которую держит строка прогона** (TDM#721). Прогон внутри дня кладёт сделки облигаций в строки книги, у
     которой отчёта позиций на дату нет (`trades.apply_intraday`, TDM#557), и пишет в строку `x.intraday_trades` —
     номера сделок, которые строка держит (в строке прогона это `extra.reported.x.intraday_trades`). Такая сделка
     «уже в позициях», как если бы позиции были датированы не раньше сделки (`held_trades`, прежде `off_report_held`;
     туда же — деривативы вне отчёта позиций, TDM#468): у облигации остаётся оплата или выручка, бумаги по цене сделки
     нет — её MV уже в переоценке облигаций. Раньше бумага считалась дважды: ногой по цене сделки и MV новой или
     изменённой строки (покупка на 500 давала +500 ОВП, продажа на 400 — −400; версия расчёта 36). Сделку, которую
     прогон в книгу не внёс (`no_instrument`, `units_mismatch` и т. п.), строка не держит, и считается она как раньше.
   - Компонента удержанной валютной сделки — компонента её строки, а не сделки (`components` в `trade_flows`: ОВП
     позиций прогона по позиции). Строку относят к споту или сроку по дате прогона, сделку — по её собственной дате:
     форвард, купленный в пятницу на среду следующей недели, в понедельник — строка `cash`; при `cash` вне отчёта строка
     уже во «вне отчёта», и сделка, нога `fx_legs` по своей дате, считалась бы второй раз. У строки без компоненты
     (нет ОВП) решает дата сделки. Валютные сделки в книгу прогона пока не входят (TDM#716): правило готово к ним.
   - Прочие типы не оцениваются (`trades_not_valued`), сделка книги, которой нет в справочнике, не входит
     (`trades_unknown_book`).
   - Сделок ни за одну дату нет — слагаемое пустое, пробел «сделки после базы не загружены: ОВП без них»
     (`trades_not_loaded`).
6. **База устарела.** Отчёта не новее `report_max_age_bd` рабочих дней нет — ОВП книг юрлица из позиций, как раньше
   (`derived_stale_report`, пробел `stale_report`). Если адаптер разрешит старше одного дня, на строке видна дата
   базы, а в пробелах `base_older`.
7. **Одна методика на все даты.** Базис и остальные поля задаёт строка `ocp_policy` адаптера (`published`). Монитор
   берёт политику, действующую сегодня (московский день: строка без `valid_from` действует всегда; из строк одного `policy_id` берётся наибольший
   `valid_from` не позже сегодняшнего дня; если все строки ключа в последней поставке датированы позже, действует строка
   прежней поставки до этого дня), и применяет её ко всем датам истории, а не ту, что действовала в каждую из них
   (решение владельца от 04.11.2026, TDM#567). Политика — снимок: ключи берутся из последней поставки адаптера (строка с датой «Действует с» в будущем оставляет прежнюю строку ключа до своего дня), строка, которую адаптер перестал присылать, перестаёт действовать (пустой список поставкой не считается). Смена политики ставит на пересчёт весь год; причина на экране «Статус
   дня» — «политика ОВП». `valid_from` в будущем только откладывает смену: в этот день пересчитывается вся история.
   Пока таблица видов в адаптере пуста, адаптер отдаёт `report_plus_outside`. Если ни одна строка `published` не задаёт,
   движок берёт `report_base_plus_day` для любой даты (VALUATION_VERSION 29).

### Фьючерсы (DEC18, решение владельца 05.11.2026, TDM#588)

ОВП фьючерсов в базовом отчёте ОВП не учитывается (по ответу владельца). Методика:

- **Валютный фьючерс** — только вид ядра `fx_future` или группа продукта отчёта ровно `fx_future`. Он даёт ОВП своим
  номиналом в базовой валюте (поле номинала отчёта позиций — номинал в базовой валюте). У кросс-курса добавляется вторая
  нога в валюте котировки: −номинал × цена; цена — кросс курсов прогона (базовая / котируемая, рубли за единицу каждой).
  У пары «валюта / рубль» рублёвая нога в ОВП не идёт.
- **Невалютные фьючерсы и опционы на них** — на облигации, ставки, индексы, акции, товары: любая группа продукта со
  словом `future`, кроме `fx_future` и `fx_future_option` (`bond_future`, `ir_future`, `equity_future`, `index_future`,
  `commodity_future`, а также `future` и `future_option` — адаптер даёт их только фьючерсам не на валюту), — номинала и
  стоимости в ОВП не дают (`rules.ocp.future_class`). В «деривативы» и «вне отчёта» они не попадают, в заметках
  прогона — «фьючерс не на валюту» (если у строки есть валютная сумма); незнакомая монитору группа со словом `future`
  считается так же, с заметкой.
- **Опцион на валютный фьючерс** (`fx_future_option`) — опцион на валюту: слагаемое «опционы» по его дельте, как
  валютный опцион.
- **Результат фьючерсов в валюте** (вариационная маржа и PnL, валютных и невалютных) и кэш FX-сделок, переносящих ОВП, —
  из отчёта остатков по счетам книги, по валютам. Книга есть в отчёте ОВП на B — эти остатки уже в базе. Книги нет в
  отчёте ОВП на B (база 0) — её остатки **на дату B** (набор `cash_balances`, действующий на B) идут отдельным слагаемым
  `balances` («остатки по счетам: книги нет в отчёте ОВП»; только у таких строк), сверху — сделки после B, как у любой
  книги: ничего не считается дважды. Последние остатки книги старше B — пробел `balances_older_than_base` (сделки между
  ними и B не вошли). На прогоне за саму дату B — остатки прогона.
- **Сделки после B** по фьючерсам дают ОВП только по валютным фьючерсам: номинал в базовой валюте (сумма в другой валюте
  переводится по курсу сделки `fx_rate`; без курса — сделка в `trades_not_valued`). Сделки по фьючерсам с невалютным
  базовым активом ОВП не дают. Слагаемого `futures` нет в отчёте — фьючерсы приходят из позиций («вне отчёта»), сделки по
  ним не считаются.
- **Проверка.** Если один вклад дериватива (PV позиции или номинал отчёта) — не меньше 0,95 суммы размеров всех вкладов
  строки, а эта сумма не меньше 10 млн долларов по курсам прогона, строка получает `derivative_share` (позиция, сумма,
  доля), пробел `derivative_share`. Пороги — умолчания монитора в коде; меняются по просьбе владельца (`DERIVATIVE_SHARE_MAX`,
  `DERIVATIVE_GROSS_MIN_USD`). Цель — ошибка единиц (номинал в миллиардах), а не хеджированная книга, у которой ОВП —
  малый остаток больших встречных вкладов.

### Сверки (видны, цифру не меняют)

- Отчёт целиком (`ocp_ccy` + номинал вынесенных видов) против ОВП из позиций — как раньше (`reconciliation`; у
  строки сверки теперь `reported_base`, `reported_derivatives`, `split_kinds`).
- Номинал отчёта против PV на B по книге и виду (`derivatives_check`): на прогоне за B — PV этого прогона, позже —
  `derivatives_pv` основного прогона за B (всегда PV). Прогон за B посчитан по другому базису (первый день после
  переключения) — PV на базу неизвестен, а не 0: `pv` пустой, пометка «PV на базу неизвестен». Большая разница — признак неполных условий сделки или типа
  строки, отнесённого не к тому виду.

### Экран C16

При новом базисе дата базы (обычно прошлый рабочий день) — только в подсказке строки («база ДД.ММ»). «Отчёт от» —
только у базы старше прошлого рабочего дня: это решает сервер по календарю прогона (`base_older` строки, в истории
`baseOlder`). Книга без строк в отчёте — «нет в отчёте». Полный разбор — #532.

## Пример на вымышленных цифрах

Юрлицо ЮЛ-1, три книги: ДЕР (деривативы), ОБЛ (валютные облигации), ВАЛ (валютная книга). Валюты USD и CNY, тысячи
единиц валюты. Отчёт держит все слагаемые, кроме опционов и NDF (их в примере нет).

### Отчёт ОВП на B = чт 15.10

| Книга | Валюта | `ocp_ccy` | `derivatives_ccy` |
|---|---|---:|---|
| ДЕР | USD | 100 | `fx_forward` +500 (форвард: купить 500 USD за CNY) |
| ДЕР | CNY | 0 | `fx_forward` −3 600 |
| ОБЛ | USD | 1 010 | `fx_forward` 0 |
| ВАЛ | USD | −250 | `fx_forward` 0 |
| ВАЛ | CNY | 2 000 | `fx_forward` 0 |

### Прогон за B (вечер 15.10, отчёт уже пришёл)

PV форварда по рынку 15.10: +490 USD, −3 540 CNY. Переоценки и сделок нет (B = D).

| Книга | Валюта | база | деривативы | облигации | сделки | ОВП |
|---|---|---:|---:|---:|---:|---:|
| ДЕР | USD | 100 | 490 | 0 | 0 | **590** |
| ДЕР | CNY | 0 | −3 540 | 0 | 0 | **−3 540** |
| ОБЛ | USD | 1 010 | 0 | 0 | 0 | **1 010** |
| ВАЛ | USD | −250 | 0 | 0 | 0 | **−250** |
| ВАЛ | CNY | 2 000 | 0 | 0 | 0 | **2 000** |

Итог юрлица: USD 1 350, CNY −1 540. Сверка номинала: USD 500 против PV 490 (разница 10), CNY −3 600 против −3 540
(разница −60).

### Прогон внутри дня D = пт 16.10

Что случилось после B: облигация заплатила купон 25 (её грязная MV упала с 1 010 до 985) и подорожала на 15 (MV
сейчас 1 000); PV форварда по рынку t: +495 USD, −3 555 CNY; ВАЛ купила 200 USD за рубли (спот).

- облигации ОБЛ: 1 000 − 1 010 + 25 = **+15** (это движение цены; купон уже стоял в базе как поток к получению,
  поэтому падение MV на купон возвращается);
- деривативы ДЕР: USD 495, CNY −3 555 (PV на t, номинал из отчёта не используется);
- сделки ВАЛ: USD **+200** (рубли ОВП не дают).

| Книга | Валюта | база | деривативы | облигации | сделки | ОВП |
|---|---|---:|---:|---:|---:|---:|
| ДЕР | USD | 100 | 495 | 0 | 0 | **595** |
| ДЕР | CNY | 0 | −3 555 | 0 | 0 | **−3 555** |
| ОБЛ | USD | 1 010 | 0 | 15 | 0 | **1 025** |
| ВАЛ | USD | −250 | 0 | 0 | 200 | **−50** |
| ВАЛ | CNY | 2 000 | 0 | 0 | 0 | **2 000** |

Итог юрлица: USD 1 570, CNY −1 555. Сверка номинала идёт против PV на B из прогона за 15.10 (490 / −3 540), не против
PV на t.

### Устаревшая база

Понедельник 19.10, утро: отчёт за пятницу 16.10 ещё не пришёл, последний — за четверг 15.10. Между ними два рабочих
дня (16.10 и 19.10), лимит — один, поэтому ОВП книг ЮЛ-1 считается из позиций (`derived_stale_report`), пробел
`stale_report` «отчёт ОВП от 15.10.2026: старше 1 раб. дн., ОВП его книг — из позиций». Когда придёт отчёт за 16.10,
он станет базой следующих прогонов понедельника (один рабочий день). Если адаптер поставит
`report_max_age_bd` = 2, база останется 15.10, переоценка и сделки — с 15.10 (сделки 16.10 и 19.10), на строке
видна дата базы, в пробелах `base_older`.

### Ещё три случая

- **Книги нет в отчёте.** Книга НОВ юрлица ЮЛ-1 без строк в отчёте на 15.10 с форвардом PV +300 USD: база 0, ОВП
  +300 USD (`book_absent`).
- **Часть отчёта перенесена.** Книга СТАР была в отчёте за 14.10 (+5 000 USD), в отчёте за 15.10 её нет. Часть за
  14.10 остаётся в силе (`covers: listed`), но в базу на 15.10 не входит: база СТАР 0, пробел «книга СТАР: последняя
  строка отчёта от 14.10.2026, в базу не входит».
- **Адаптер до 1.7.** В строке ДЕР USD отчёт даёт 600 (100 кэш + 500 номинал форварда одной цифрой), поля
  `derivatives_ccy` нет: ОВП 600, PV не добавлен, пробел `report_without_derivatives_split`.

## Договор с адаптером (`private/1.7`)

- `ocp.derivatives_ccy` — необязательный объект «вид дериватива → номинал строк отчёта этого вида с датой
  валютирования позже даты отчёта, убранных из `ocp_ccy`». Ключи — `fx_forward`, `fx_swap`, `fx_future`, `ndf`,
  `fx_option`, `swap`, `other` (другие — `bad_value`), суммы как везде, ноль сохраняется. Ключ, хоть «0», значит: вид
  вынесен для всего файла. Поле каноническое, входит в хеш ревизии. `ocp_rub` следует за `ocp_ccy`. В CSV эталонного
  адаптера — `fx_forward=-1000000,ndf=0`, `{}` — пусто; ключ дважды — берётся последний, предупреждение
  `duplicate_object_key`.
- `ocp_policy.published` = `report_base_plus_day` (действует на все даты; без строки — движок),
  `ocp_policy.report_max_age_bd` — возраст базы в рабочих днях (по умолчанию 1).
- Адаптеры 1.0–1.6 принимаются без изменений.

### Строки спот-типа с будущей датой (TDM#693, решение владельца 12.11.2026)

Отчёт ОВП записывает номинал части FX-деривативов (NDF, в том числе кросс, форвард, фьючерс) строкой типа «спот» на дату
расчётов. Такая строка в базе, а монитор добавляет ту же сделку ещё раз из позиций или условий: двойной счёт, к тому же
недисконтированный. Адаптер перечисляет такие строки в поле строки `ocp` `spot_future` (штатное поле договора private/1.9, TDM#703; в
хеш ревизии входит, поэтому уже принятый отчёт, перечитанный адаптером 1.9, получает новую ревизию, и ОВП его даты
считается заново; адаптер 0.9.14 отдавал их в `x_spot_future`, монитор читает его, пока у строки нет `spot_future`):
`[{src, value_date, pair, amount_ccy}]` — строка спот-типа с датой позже окна спота (дата отчёта
плюс `settle_window_bd` рабочих дней). Отдельными строками набора их выдать нельзя: ключ `ocp` — (юрлицо, книга, валюта).
Они остаются в `ocp_ccy`: монитор без разбора, как раньше, держит их в базе.

Монитор (`rules/ocp_spot.py`, `ocp.spot_deals`, `published_day`) сопоставляет строку со сделкой (форвард, NDF, фьючерс):

1. та же книга (строка без книги — любая книга области);
2. валюта строки — валюта одной из ног сделки (ноги — из условий сделки: покупка даёт +базовая и −котируемая; без
   условий — `extra.ocp_amount` или FX-дельта строки позиции);
3. сумма строки равна номиналу ноги со знаком в пределах `max(1, 1e-6 × |номинал|)` (для ноги, которой в условиях нет и она
   выведена из курса сделки, — `1e-4`);
4. дата строки — в пределах пяти рабочих дней от даты сделки (расчётов, валютирования или фиксинга).

Замена идёт по паре (позиция, валюта): только нога, по которой нашлась строка, заменяется экспозицией сделки; остальные ноги
сделки считаются по прежнему правилу, это сказано в пробеле `spot_future_partial`. Строка берёт одну сделку, нога сделки —
одну строку (если строке не досталась сделка, ищется перестановка уже сделанных пар); при нескольких кандидатах — ближайшая по дате, остальные названы
(`spot_future_ambiguous`). Сопоставленная строка **всегда** выносится из базы (слагаемое `base`, вклад `report_spot_future`
с отрицательной суммой), вместо неё в ОВП — экспозиция сделки:

- сделка оценена ядром — её PV, как и раньше (по правилу вида: вид вынесен отчётом, компонент в отчёте, поток после B;
  иначе она добавляется здесь же вкладом `derivatives` с пометкой «сопоставлена со строкой отчёта спот-типа»);
- сделка не оценена, условия известны (нет кривой валюты, `extra.risk_missing`, или другая причина) — номиналы её ног
  без дисконтирования (дисконт-фактор 1): кросс-NDF — нога базовой валюты и нога котируемой (−номинал × курс сделки из
  условий), пометка «нет кривой <валюта>: дисконт-фактор 1», пробел `spot_future_df1`; ноги идут в `derivatives` своих
  валют, строка позиции в свой вид не попадает;
- компонент сделки вне отчёта — сделка уже в слагаемом `outside`, строка просто выносится из базы; у неоценённой
  сделки с условиями в сопоставленной валюте `outside` заменяет нога по номиналу с дисконт-фактором 1.
- замена идёт по паре (позиция, валюта): несопоставленная нога сопоставленной сделки считается по прежнему правилу
  своего вида, пробел `spot_future_partial`.

Несопоставленная строка остаётся в базе по номиналу (`spot_future_unmatched`). Строка `published.by_book` несёт
`spot_future: {out, unmatched, df1}` — разбор на C16, раздел «Строки отчёта спот-типа с будущей датой». Версия расчёта 35.

## Что не входит

- Экран разбора цифры (#532).
- Сопоставление типов строк с видами и авто-книги — в приватном адаптере. Экран монитора для него — «ОВП: типы
  строк отчёта» в Настройках (TDM#554): данные экрана даёт действие адаптера (`choices`, 08 §3), кнопка «Сохранить и
  пересчитать» пишет соответствие во вкладку адаптера, перечитывает последний отчёт (`/api/v1/inbox/replay`, TDM#553),
  а автообновление сразу пересчитывает сегодняшний прогон (новая ревизия отчёта после прогона — `backfill.late_why`).
- Кросс-сделка без рублёвой ноги: набор `trades` даёт одну валюту на строку, вторая нога кросса пока не учитывается.
- Срочная сделка переноса ОВП: монитор держит её в слагаемом `transfers`, вид — по продукту (`fx_forward`); проверить
  на данных, когда придёт разметка.
- История прогонов не пересчитывается: старые прогоны хранят свой базис и показываются как раньше.
