# Экран × величина × источник: инвентаризация (TDM#535, шаг 1)

Ревизия 1, 04.11.2026. Шаги 1–2 эпика FlyingScotman/trading-desk-monitor#535 по трём вопросам владельца:
фильтр книг (FlyingScotman/trading-desk-monitor#566), ОВП из одного источника
(FlyingScotman/trading-desk-monitor#567), PnL сделок дня во всех PnL (FlyingScotman/trading-desk-monitor#568).
Документ описывает код ветки интеграции после FlyingScotman/trading-desk-monitor#557 (сделки дня) и
FlyingScotman/trading-desk-monitor#531, #556 (ОВП «база отчёта + день»); исправлений в нём нет. Ссылки на код —
`файл:строка` на момент ревизии. Примеры и формулировки — синтетические (ADR-008).

## Обозначения

- **Шапка** — фильтр мониторов `K.filter` = `{entity, desk, books, ccy, portsOff}` (`prototypes/concepts/lib/kit.js:667-670`,
  хранится в `localStorage['concepts-filter']`). `portsOff` — снятые портфели (колонка портфеля отчёта, `x_portfolio`).
- **K.list** — позиции прогона под шапкой (`kit.js:678`): юрлицо и деск позиции — из справочника книг прогона
  (`real.js:366`), книга, валюта позиции, портфель `p.portfolio`. Считается в браузере.
- **M** — модель мониторов из двух ответов: `/concepts-run.js` (`api/concepts_run.py`, позиции, ОВП, фондирование) и
  `/concepts-data.js` (`api/concepts.py:extras`, история деска, MTD/YTD позиций, потоки, рынок); сборка — `lib/real.js`.
- **История деска** `M.hist` — суммы каждого основного прогона по всем позициям (`publish/summary.py`, таблица
  `run_summary`; `concepts.py:186, 263-267`): PnL по факторам, DV01 по кривым и книгам, CS01, MV по типам и валютам.
- **Публикуемая ОВП** — блок `ocp` прогона (`publish/ocp_run.py`, v3): `published.by_book` по книгам и частям отчёта
  по юрлицу, методика `basis` (`report_base_plus_day` — отчёт за прошлый рабочий день без деривативов, которые он даёт
  отдельно, плюс их PV и изменения дня; `report_plus_outside` — отчёт своей даты целиком; `derived` — из позиций).
- **Факторы PnL мониторов** (`kit.js:283`, `real.js:477`): кэрри = carry + rolldown, фондирование, ставки = rates +
  convexity, спред, FX = fx_gross + fx_funding (`summary.fx_net`), **сделки = `new_trades`**, прочее = other +
  reported; итог дня = `explained` = сумма всех компонент (`concepts_run.py:129-139`).
- **PnL за период** (C19) — `/api/v1/history/pnl/period|curves|position|checks` (`api/pnl_period.py`,
  `api/pnl_history.py`, `api/pnl_checks.py`): сумма сохранённых компонент `run_position.pnl` по строкам периода,
  фильтр на сервере (`pnl_history.rows_query`, `:224-247`).

### D1 [фильтр] История деска рядом с отфильтрованными цифрами без подписи

`M.hist` — суммы прогонов по всем позициям (`concepts.py:186, 263-267`; `summary.py` `build`), фильтр шапки к ней не
применяется. Подписано на C05, C10, C11, C12; не подписано: C01 «PnL за 130 дней» и вкладка «История»
(`c01-cockpit.html:88-91, 98-111`), C06 KPI-спарки и плитка «PnL дня: разложение» в режиме «30 дней» (в той же плитке
режим «водопад» — под фильтром; `c06-launchpad.html:91-93, 158-167`), спарк PnL в шапке и на C10 (`kit.js:3266`,
`c10-pnl-explain.html:92`). C05 при фильтре масштабирует историю долей (`c05:185`).
Исправление: ряды по книгам (в `run_summary` уже есть `dv01Book`; добавить PnL по книгам и факторам) и сумма по
фильтру на клиенте; до этого — подпись «весь деск» везде, где ряд стоит рядом с цифрами под фильтром. Объём: подпись S,
ряды по книгам M (новая версия `summary.VERSION`).

### D2 [фильтр] «Без HTM» и портфель позиции — три разных правила

**Закрыто в FlyingScotman/trading-desk-monitor#566: правило в `backend/src/desk/api/scope_rule.py` (тип книги HTM, затем колонка отчёта последней строки набора, затем колонка из extra строки прогона, затем «без портфеля»); им пользуются `concepts_run`, `compat` и `pnl_history.DIMENSIONS`; `LIMIT 1` без `ORDER BY` убран. Клиент берёт поле `portfolio`.**

- Шапка и все мониторы: `p.portfolio` = `x_portfolio` строки входа, найденной **только по id позиции** среди наборов
  прогона (`concepts_run.py:282-285, 314`; так же `compat.py`), тип книги не учитывается (`kit.js:678`).
- C19: `x_portfolio` строки входа по id и книге, `LATERAL … LIMIT 1` без `ORDER BY` (`pnl_history.py:182-189`), фильтр
  `ports_off` (`:236-238`); тип книги не учитывается.
- C16: тип книги из справочника (`K.ocpScope`, `F.type`, `kit.js:3198`), портфели не применяются.
- ОВП шапки и C06: портфели не применяются вовсе (сказано заметкой, `kit.js:3217`).

Решение владельца по FlyingScotman/trading-desk-monitor#496 (книга с `book_type = HTM` → все её позиции HTM, иначе
портфель из отчёта) нигде не реализовано; задача открыта. Исправление: «эффективный портфель» считать на сервере в
одном месте и отдавать полем в `concepts_run` (позиции), `pnl_history` (`DIMENSIONS`, `catalogue_rows`) и `compat`;
`K.list` и `K.ocpScope` берут поле, не пересчитывая. Объём M.

### D3 [фильтр][сделки] Строки «закрыто сегодня» и позиции, открытые сделками, без портфеля

**Портфель таких строк (запасной источник — колонка в `fact.extra`) учтён в правиле #566; саму колонку проставляет пакет #570.**

Проданная до нуля облигация книги с отчётом держит PnL на строке с нулевым количеством, при занятом id —
`<id>|closed` (`trades.py:396-402`); позиция, открытая сделкой в книге без отчёта, — новая строка (`trades.py:360-363`).
Портфель читается из таблицы входов по id (`concepts_run.py:282-285`, `pnl_history.py:182-189`), у таких строк его
нет → «без портфеля» (`—`). Под фильтром портфелей PnL сделок дня этих строк уходит в «без портфеля» или пропадает.
Исправление: в том же правиле D2 брать портфель исходной строки (её `extra.x`) для строк, построенных сделками.
Объём S (вместе с D2). Проверено по коду; синтетического теста нет.

### D10 [ОВП] Два сериализатора одного блока ОВП и разный справочник книг
