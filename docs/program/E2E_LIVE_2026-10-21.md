# Приёмочный прогон на живых данных хаба, 21.10.2026

Сквозная проверка приложения так, как его запускает владелец: отчёты позиций в папке → `desk inbox scan` →
`desk history sync` → `desk eod` → `desk backfill` → `desk serve` с автопилотом, затем все концепты C01–C13,
Desk Monitor и «Настройки» в браузере (Playwright) против демо-версии (`?demo=1`). Рынок — production
`marketdatahub.cc` (только чтение, GET), портфель — синтетический, на настоящих бумагах статики хаба.

## 4. Исправлено

1. **Субфедеральные и «прочие» бумаги** (группы `SUB`, `OTH` прогона) выпадали из таблиц C01, C02, C04 и фильтров C07,
   C12: страницы знали только группы демо (`GOV`, `CORP`, `DER`). `KIT.GROUPS`, подписи групп в `kit.js`.
2. **Сделки дня** (`concepts.extras`): сравнивались с предыдущим прогоном в истории, а не с прогоном предыдущего закрытия
   — пока история досчитывалась, «сделками сегодня» были все 210 позиций; номинал линкера (индексация) и
   амортизационной бумаги менялся сам и давал ложные сделки. Теперь — только против прогона `prev_date`, по числу
   бумаг; без такого прогона — заметка «нет прогона за …». Тест.
3. **Backfill**: ошибка соединения с хранилищем, сети, диска или хаба целиком записывалась как «дата не посчиталась» и
   дата больше не считалась никогда (20 дат после падения PostgreSQL). Теперь прогон останавливается, дата не
   запоминается. Тест (хранилище и хаб).
4. **Календарь рынка**: оферта, которую хаб перечисляет дважды (cbonds и MOEX ISS — 557 из 4 403), считалась дважды.
   `static_facts.VERSION` 2 — строки пересоберутся при ближайшем прогоне. Тест.
5. **C11**: ряды риска по кривым не обрезались вместе с датами → «Кривые» нулями; на прогоне внутри дня «Δдох.»
   считалась от пустой доходности (−1 671 б.п.) — теперь берётся доходность прогона.
6. **Список кэша срезов**: каждый процесс заново распаковывал и разбирал все бандлы (190 файлов, 1.4 ГБ JSON — 54 с на
   старте `desk backfill`, `desk eod`, `desk cycle`, «Истории прогонов»). Индекс `.manifests.json` в папке кэша:
   0.8 с. Тесты.
7. **C05**: числа без округления, фраза о рынке по данным (направление, бакет, знак базиса), «нет данных» для кривых
   USD/CNY, Минфин не «концентрация»; курс, по которому посчитан FX-PnL (ЦБ), рядом с рыночным.
8. **C09**: шкала карты 0…30%, рейтинги — «нет данных» с причиной и сравнение «без рейтинга», медиана без пустых
   спредов, подписи ОФЗ на карте не перекрывают точки.
9. **C13 / C06 / C05**: Минфин по флагу `gov` статики (а не по id демо `MINFIN`); короткие имена эмитентов; панели
   секторов и рейтингов — «нет данных: … в статике хаба нет».
10. **Валюта отчёта USD**: PnL позиций без PnL становился 0 при пересчёте (null × курс).
11. **Desk Monitor**: подпись среза прогона из базы («21.10 18:30 МСК · внутри дня»).
12. `smoke.js --base` находит строки позиций прогона (id «книга|бумага»).

## 6. Осталось (с причинами)

1. **Рейтингов и секторов в хабе нет** (статика: `rating` 0%, `sector` 0%): C09 «G-спред по рейтингам», C13 «по
   секторам / по рейтингам», C07 «сектор → эмитент», раскраска карты C09 — «нет данных» или одна группа. Нужен
   источник в хабе (HS3/рейтинги).
2. **Курс FX-бондов.** Флэш оценивает валютные бумаги по курсу ЦБ, действующему на дату (`fallback.fx_rate`), а цены
   замещающих облигаций MOEX рассчитываются в рублях по курсу ЦБ на дату расчётов (T+1). Когда ЦБ меняет курс
   скачком, FX и «прочее» по валютным бумагам гасят друг друга: курс ЦБ, действующий на дату, отстаёт от цены на
   день (20.10: крупные FX и «прочее» разных знаков при почти неподвижном рынке). ORG_CONVENTIONS §2.2 называет
   основным рыночный PnL по курсам ~19:00 — нужно решение владельца; страницы теперь показывают оба курса.
   **Решено 21.10 (R26):** валютные бумаги и FX-строки — по курсу MOEX 19:00 (запасные 14:00 → CETS → ЦБ); на
   выборке USD-бумаг 20.10 FX стал малым, «прочее» почти не изменилось, крупный FX по курсу ЦБ показан рядом.
3. **28.09.2026 в рынке хаба нет кривой RUONIA OIS**: прогон дисконтирует по КБД, все бумаги «assumed», базис ОФЗ в
   истории C11 проваливается до −12.8 млн/бп на один день (обычно −21.4). Пробел данных хаба.
4. **Прогоны внутри дня**: все облигации «assumed» с пометкой «accrued computed: no MOEX accrued» — в
   внутридневных котировках нет НКД. Стоит считать НКД по графику «точным» для известных купонов.
5. **Desk Monitor «PnL за 22 дня: официальный и explained»**: пока официального нет, «официальный» = explained +
   курсовая разница ЦБ (паритет с tdm), линии совпадают. Подпись вводит в заблуждение.
6. **Кривых USD/EUR/CNY в хабе нет**: риск валютных бумаг — по дюрации, на кривых «USD/EUR/CNY» без точек; сдвигов
   нет («нет данных» в C05).
7. **Оферты в календаре рынка** — на весь объём в обращении («возможный объём»): ноябрь 2026, корп. фикс — 3.5 трлн ₽,
   в основном оферты Роснефти. Так задумано, но картина без вероятности исполнения.
8. **Дефолтные бумаги** показывают доходности MOEX как есть (29 574%, 4 187%) в таблицах C03 и «наших против рынка».
9. **Карточка позиции** 1.5–1.9 с: глубокая история запрашивается синхронно на каждую карточку.
10. **Пересборка статических фактов** после смены их версии происходит при ближайшем `desk eod` / прогоне внутри
    дня, а не на ближайшем цикле автопилота (документ модуля говорит обратное).
11. **Среда**: встроенный PostgreSQL работает под пользователем `pgserver` и терял доступ к данным в рабочей папке
    агента (права 700 на родителе выставляются средой): падение посреди backfill. Для прогона хранилище вынесено
    (`DESK_STORE_URL`). У владельца (Windows, `%LOCALAPPDATA%`) этого нет; последствие для backfill исправлено (п. 4.3).
