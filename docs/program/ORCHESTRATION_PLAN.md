# План работ оркестратора (с 20.10.2026)

Центральная точка разработки Trading Desk Monitor: эта сессия-оркестратор раздаёт поручения агентам, ведёт roadmap и процесс, управляет ветками этого репозитория и смежных (`trades-data-adapter`, `market-data-hub`, `rub-fixed-income-core`). Запросы владельца и их статусы — [OWNER_REQUESTS.md](OWNER_REQUESTS.md) (R1…); этот файл — как и в каком порядке они делаются.

## 1. Процесс

1. Владелец пишет темы → оркестратор сразу заносит их в OWNER_REQUESTS.md (статус todo/investigate).
2. Неясная причина → сначала агент-исследователь без правок (отчёт: причина, file:line, предложение по исправлению). Затем исправление.
3. Исправления делают агенты в отдельных git worktree, коммитят в свою ветку, не пушат. Оркестратор сливает их в рабочую ветку, решает конфликты, прогоняет `cd backend && .venv/bin/pytest -q` и `python3 -m unittest discover -s tests` в корне, проверяет страницы в браузере (Playwright, Chromium в `/opt/pw-browsers`), пушит.
4. Зоны файлов между параллельными агентами не пересекаются. Если пересечение неизбежно, задача уходит агенту, который уже правит эти файлы (SendMessage).
5. Выпуск: одна Windows-сборка на волну. Владелец ставит её один раз вручную, дальше обновляется кнопкой (R3). Для подтверждения диагноза владельцу даются точные команды сбора логов, с объяснением каждой команды, флага и операнда.
7. Порт по умолчанию — 8100 (R12): http://127.0.0.1:8100/.
6. Правила данных: реальных отчётов и значений в Git нет; в логах только коды и счётчики.

## 5. Решения, принятые оркестратором 20.10

- Файлы, которые адаптер не берёт или которые старше окна, не хешируются и не попадают в журнал: они хранятся в `inbox_unread` по ключу (путь, размер, mtime). В спеке 08 отмечено, что вызовы адаптера в рамках скана делят долгоживущие процессы.
- Порядок обработки отчётов (новые первыми) не влияет на результат: ревизии решаются ключом ревизии (08 §6.6). Тест параметризован на 1 и 3 процесса.
- Автопилот считает последнюю дату позиций первой, если у неё ещё нет прогона. Модельные спреды тогда переносятся из уже существующих прогонов; цена — возможная разница только у облигаций на модельной цене.
- Число процессов чтения — переменная окружения `DESK_INBOX_READ_WORKERS` (по умолчанию до 4), без поля в settings.json, чтобы не пересекаться с параллельными правками `settings.py`.
