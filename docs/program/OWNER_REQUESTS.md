## Заметки по R1/R2 (что изменено)

- Файл сначала сопоставляется адаптером по имени, без чтения и хеширования. Неподходящие файлы (`ignored`) и файлы с датой отчёта старше окна (`ignored_too_old`) запоминаются по пути, размеру и времени изменения (`inbox_unread`). Следующие сканы их не трогают: только листинг папки. Повторно такой файл предлагается адаптеру, если он изменился, сменился адаптер или его настройки, либо окно `inbox_lookback_days` расширилось.
- Адаптер работает в долгоживущих процессах на время скана, а не в отдельном процессе Python на каждый вызов: импорт адаптера и загрузка справочника инструментов происходят один раз.
- Чтения идут параллельно (`DESK_INBOX_READ_WORKERS`, по умолчанию до 4 процессов), самые свежие отчёты первыми.
- `reference()` (книги, в том числе автокниги, ради которых адаптер читает 5 последних отчётов) запускается только когда есть что читать или после смены адаптера или его настроек. Раньше это происходило на каждом цикле автопилота, раз в минуту.
- Файлы в ожидании календаря сопоставляются заново только после появления новых статических снапшотов. Справочник инструментов пересобирается, только когда меняется набор снапшотов.

## Заметки по R7 (графики цен и доходностей)

Причины (исследование 20.10):
- Падение JS. У облигации с доходностью, но без даты погашения (например, бессрочной на резервной оценке), карта доходностей падает (`toFixed` от null). Вместе с ней пропадают и карта, и «История выпуска». Это и есть «интерфейс исчез».
- Почти нет данных. История строится только по дням, за которые есть прогоны (1–2 точки). Линия из одной точки не рисуется (`showSymbol: false`). Спреда к кривой нет.
- Облигацию без ISIN нельзя выбрать.

Исправления:
- (а) JS: карта и история не роняют друг друга, точки видны, выбор по ключу, а не по ISIN.
- (б) История по всем дням котировок из кэша снапшотов (таблица `md_bond_eod`), доходность кривой КБД на сроке бумаги и спред к ней.
- (в) Глубина около года: автопилот догружает старые даты хаба понемногу за цикл (`history_days`).
- Правильно в итоге: эндпоинт истории на хабе (план 05 §2).

## Заметки по R8 (риски по кривым)

Сейчас всё сводится к одной кривой «RUB OFZ»:
- Флоатеры теряют риск RUONIA и ключевой ставки (сальдо около нуля).
- Валютные облигации без процентного риска (только FX-дельта).
- Отчётный DV01 (OTC, несопоставленные бумаги) всегда идёт на RUB OFZ.
- ОФЗ-ИН получают номинальный DV01 по дюрации (прокси).

Фаза 1 (в работе):
- Риск по кривым ядра: RUB OFZ (КБД), RUB RUONIA, RUB KEY.
- Сценарии по кривым.
- Валютные облигации: дюрационный прокси на кривой своей валюты.
- Отчётный риск на кривой валюты строки.

Фаза 2 (недели):
- CNY-облигации через ядро на кривой `cny_ruonia_xccy` (данные на хабе уже есть).
- USD/EUR — когда хаб даст дисконт-кривые.
- ОФЗ-ИН — с CPI.
- OTC — с условиями сделок в приватном контракте 2.0.

**Решение владельца 20.10:** корпоративные облигации и ОФЗ дисконтировать против RUONIA (RUONIA OIS + спред). Сделано (cf1c774): рублёвые облигации (ОФЗ и корпоративные, фикс и флоатеры) дисконтируются по RUONIA OIS + Z-спред к цене; Z-спред, CS01 и чувствительность к спреду ОФЗ — к RUONIA; КБД остаётся для G-спреда, графика кривой и истории. DV01 по RUB OFZ — только в день, когда кривой RUONIA нет (тогда дисконт по КБД с пометкой `assumed`). Отчётный рублёвый DV01 — на RUB RUONIA. PnL ставок пересчитывается по всем кривым бумаги (`desk-flash-exact-v2`): у флоатеров «прочее» ≈ 0. Итоги прогона включают `fx_gross`.

Открыто: CS01 валютной облигации = её дюрационный прокси или 0 (вопрос владельцу); старые прогоны держат риск на RUB OFZ; оставшаяся фаза 2 — CNY на `cny_ruonia_xccy`, USD/EUR — когда хаб даст кривые, ОФЗ-ИН с CPI, OTC с условиями сделок.
