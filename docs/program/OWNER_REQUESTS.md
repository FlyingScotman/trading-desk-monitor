## Заметки по R25 (как проверить)

Команды — в окне командной строки в папке программы, после обновления.

1. `desk.bat sync --last 1` — `sync` скачивает с хаба срезы, `--last 1` — только последний рабочий день. Теперь в
   конце есть строка `newest static <id> of <дата>, published <время>: downloaded | cached (issuer facts and ratings
   of the runs and pages)` — это новейшая статика хаба, из которой берутся имена, группы, секторы и рейтинги.
2. `desk.bat eod --date 2026-10-21` — `eod` пересчитывает закрытие, `--date` — его дата (ГГГГ-ММ-ДД; взять
   последний рабочий день). Автопилот сделает это и сам (версия расчёта 8), команда нужна, чтобы увидеть строку
   `справочник эмитентов и рейтинги: статика <id> от <дата> (market_snapshot/1.2) (новее статики рынка …); рейтинг
   у N из M облигаций (рейтинг выпуска …, уровень эмитента по выпускам …, нет …); сектор у K из L эмитентов`.
   «строк рейтингов в статике нет» в ней — хаб ещё на статике без рейтингов.
3. `desk.bat instruments export --out instruments.xlsx` — `instruments export` выгружает все бумаги новейшей
   статики так, как их видит монитор, `--out` — файл (`.csv` или `.xlsx`). Колонки `rating` (грейд деска или «б/р»),

## Заметки по R1/R2 (что изменено)

- Файл сначала сопоставляется адаптером по имени, без чтения и хеширования. Неподходящие файлы (`ignored`) и файлы с датой отчёта старше окна (`ignored_too_old`) запоминаются по пути, размеру и времени изменения (`inbox_unread`). Следующие сканы их не трогают: только листинг папки. Повторно такой файл предлагается адаптеру, если он изменился, сменился адаптер или его настройки, либо окно `inbox_lookback_days` расширилось.
- Адаптер работает в долгоживущих процессах на время скана, а не в отдельном процессе Python на каждый вызов: импорт адаптера и загрузка справочника инструментов происходят один раз.
- Чтения идут параллельно (`DESK_INBOX_READ_WORKERS`, по умолчанию до 4 процессов), самые свежие отчёты первыми.
- `reference()` (книги, в том числе автокниги, ради которых адаптер читает 5 последних отчётов) запускается только когда есть что читать или после смены адаптера или его настроек. Раньше это происходило на каждом цикле автопилота, раз в минуту.
- Файлы в ожидании календаря сопоставляются заново только после появления новых статических снапшотов. Справочник инструментов пересобирается, только когда меняется набор снапшотов.

## Заметки по R7 (графики цен и доходностей)

Причины (исследование 20.10):
- Падение JS. У облигации с доходностью, но без даты погашения (например, бессрочной на резервной оценке), карта доходностей падает (`toFixed` от null). Вместе с ней пропадают и карта, и «История выпуска». Это и есть «интерфейс исчез».
- Почти нет данных. История строится только по дням, за которые есть прогоны (1–2 точки). Линия из одной точки не рисуется (`showSymbol: false`). Спреда к кривой нет.
- Облигацию без ISIN нельзя выбрать.

Исправления:
- (а) JS: карта и история не роняют друг друга, точки видны, выбор по ключу, а не по ISIN.
- (б) История по всем дням котировок из кэша снапшотов (таблица `md_bond_eod`), доходность кривой КБД на сроке бумаги и спред к ней.
- (в) Глубина около года: автопилот догружает старые даты хаба понемногу за цикл (`history_days`).
- Правильно в итоге: эндпоинт истории на хабе (план 05 §2).

## Заметки по R8 (риски по кривым)

**Как проверить** (Windows: `desk.bat` вместо `desk`; каждая команда — из папки программы):

1. `desk sync --from 2026-10-19 --to 2026-10-20` — скачать финальные срезы двух дат с хаба в кэш
   (`--from` / `--to` — первая и последняя дата торгов).
2. `desk eod --date 2026-10-20 --sync` — посчитать закрытие 20.10 (`--date` — дата торгов, `--sync` — сначала
   подтянуть срезы этой и предыдущей даты). В журнале прогона строка «флэш-PnL … fx_gross …» — FX по 19:00.
3. `desk eod --date 2026-10-20 --report-dir C:\desk\reports` — то же и отчёт сверки с MOEX
   (`--report-dir` — куда положить `validation_2026-10-20.html`): колонка «Δy wap» у фикс. бумаг — сотые б.п.
4. Desk Monitor → PnL: в шапке «FX флэша: USD … MOEX 19:00 (ЦБ …)»; столбец «Курсы ЦБ» водопада — разница с ЦБ.
5. C10 (PnL explain): под водопадом строка «PnL FX по курсу … — MOEX 19:00 · ЦБ …». C06, плитка FX — то же.
   C05, «Рынок»: курс, источник и курс ЦБ рядом.
6. C03 → карточка флоатера на КС: «Дисконт-маржа» меньше Z-спреда; у ОФЗ-ПК — равна. Фикс. бумага: «G …» — ядра.
7. C02 (лестница) → CS01 по бакетам: длинная ОФЗ и корпоративная показывают риск по всей кривой, а не в двух
   соседних бакетах; кривая «ОФЗ-базис» — так же.
8. Тесты: `cd backend` и `.venv\Scripts\python -m pytest tests\test_golden_live_2026_10_20.py tests\test_core_033.py`
   (`-m pytest` — запустить тесты; файлы — золотые цифры живого хаба 19–20.10 и проверки ядра 0.33).
