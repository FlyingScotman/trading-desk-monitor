1. РАСПАКОВАТЬ
   - Сначала: правой кнопкой по zip -> Свойства -> галочка «Разблокировать» -> ОК.
   - Распакуйте в C:\DeskMonitor. Не в «Загрузки», не на рабочий стол, не в Program Files:
     в пути не должно быть пробелов и русских букв.

2. ЗАПУСТИТЬ: двойной щелчок по start.bat.
   Первый запуск ставит окружение (1-3 минуты) и открывает в браузере страницу настроек.
   Окно start.bat не закрывайте: пока оно открыто, Desk Monitor работает.

3. ХАБ (страница настроек, http://127.0.0.1:8100/settings.html)
   - адрес хаба и токен. Токен выдаётся на сервере хаба, право (scope) read
     (mdhub tokens create tdm-history -s read --expires-days 365); с правом snapshots истории не будет;
   - кнопка «Проверить связь» - должна ответить без ошибки (видна последняя дата хаба);
   - если в сеть выходят через прокси - поле «Прокси» (например http://proxy:3128).

4. ПАПКИ С ОТЧЁТАМИ: «+ Добавить папку» -> папка, куда приходит утренний отчёт по позициям,
   подпись «Позиции». Папку с PnL тоже можно добавить, но PnL пока не обрабатывается.

5. АДАПТЕР загружается сам из папки adapter этого архива - ничего указывать не нужно.
   - Книги создаются автоматически из отчёта (юрлицо + книга).
   - Позже, для красивых названий и типов книг, в разделе «Файлы настроек адаптера»
     можно заполнить books.json.
   - Имя файла отчёта задаёт patterns.json. По умолчанию ожидается гггг-мм-дд.xlsx
     (например 2026-10-20.xlsx). Если файлы называются иначе - поправьте шаблон там.
   - Знак и валюта NPV/DV01 деривативов: options.json -> report_risk.

6. ПРОВЕРИТЬ
   - На главной (http://127.0.0.1:8100/) в шапке нажмите «Обновить» (или подождите минуту -
     автопилот сам заберёт снапшоты, отчёт и посчитает EOD). Ссылка «Настройки» - там же.
     Мониторы: http://127.0.0.1:8100/concepts/index.html.
   - Что смотреть: дата прогона в шапке мониторов; позиции в C03 «Позиции» (облигации,
     которых нет на хабе, будут «не оценено»).
   - Выбор юрлиц и книг запоминается между прогонами и перезапусками.

7. ГДЕ ДАННЫЕ И КАК ОБНОВЛЯТЬ
   - Данные и настройки: %LOCALAPPDATA%\DeskMonitor (или C:\DeskMonitorData, если в имени
     пользователя русские буквы; start.bat печатает путь). Папка программы их не содержит.
   - Новая версия с GitHub: программа сама замечает её (в шапке страниц появится «Новая
     версия ...»). Настройки -> «Обновление программы» -> «Обновить до ...»: архив скачается
     (сервером или браузером в папку «Загрузки»), контрольная сумма сверится, программа
     перезапустится сама. Если не скачивается - там же «Диагностика связи» покажет, какой
     путь работает и что сказать ИТ. Откат: кнопка «Вернуть ...». Адаптер не меняется.
     Там же видно, когда программа в последний раз спрашивала GitHub и с каким итогом.
   - Релиз на GitHub создаётся только тегом v<версия> (например v0.2.5: git tag v0.2.5,
     затем git push origin v0.2.5), а не вручную кнопкой «Create release» на GitHub. Релиз,
     созданный вручную или с тегом без «v» (0.2.5), остаётся без файлов обновления: программа
     напишет «последний релиз ... без файлов обновления» и предложит предыдущий релиз с файлами.
     Такой релиз и его тег удалите на GitHub и создайте тег с «v».
   - Обновление из браузера: Настройки -> раздел «Обновление программы». Положите zip новой
     версии (полный DeskMonitor-....zip или заплатку DeskMonitor-patch-....zip) в папку
     обновлений (путь задаётся там же, можно сетевую папку) или нажмите «Загрузить zip
     с компьютера», затем «Установить». Окно start.bat не закрывайте: программа сама
     перезапустится (около минуты), страница обновится. Не запустилась новая версия -
     вернётся прежняя, причина будет на странице.
   - Вручную (в первый раз, пока установлена версия без этого раздела, или если страница
     так советует, например при новом Python): stop.bat в старой папке, затем распакуйте
     новую версию в ту же или другую папку и запустите её start.bat.
   - Настройки, токен и данные сохраняются; последний день после обновления пересчитается сам.

7а. РЕЗЕРВНЫЕ КОПИИ БАЗЫ И ПРОВЕРКА ВОССТАНОВЛЕНИЯ
   Копию базы (позиции, прогоны, история, пользователи, журнал) Desk Monitor делает сам раз в день,
   пока открыто окно start.bat: ни службы Windows, ни Планировщика заданий, ни прав администратора.
   - Когда: в 20:30 по часам компьютера; был выключен - сразу при следующем запуске.
   - Сколько: 14 последних копий, старые удаляются сами. Каждая копия - файл
     desk-ГГГГММДД-ЧЧММСС-nightly.dump и рядом .json (сколько строк в каждой таблице).
   - Где: папка backups в папке данных. ЛУЧШЕ ДРУГОЙ ДИСК или сетевая папка: если откажет диск
     с базой, копии на нём пропадут вместе с ней (страница об этом предупреждает).
   - Кто может читать: в копиях позиции и данные прогонов. Папка backups в папке данных
     (%LOCALAPPDATA%\DeskMonitor) доступна только вашей учётной записи. Новая папка в корне
     другого диска (например D:\DeskBackup) или сетевая папка обычно наследует права, при которых
     её читают все пользователи компьютера или сети. Выбирайте папку, которую читаете только вы:
     правой кнопкой по папке -> Свойства -> Безопасность - в списке только вы (и администраторы);
     для сетевой папки спросите администратора. Страница предупреждает о папке вне вашего профиля.
   Всё это меняется на странице: Настройки -> «Резервные копии» (время, сколько хранить, папка);
   там же «Создать копию сейчас», список копий и «Проверить восстановление».

   Команды (Пуск -> cmd, в папке программы:  cd /d C:\DeskMonitor ):
     desk.bat backup
       - backup - сделать копию сейчас (сервер может работать). Печатает файл, размер и число строк.
     desk.bat backup --list
       - --list - список копий, где лежат и итог последней проверки восстановления.
     desk.bat restore
       - restore - ПРОВЕРКА восстановления самой новой копии: она разворачивается во временную базу
         рядом с рабочей, число строк каждой таблицы сверяется с записанным при копировании, схема
         обновляется до этой версии программы; временная база удаляется. Рабочие данные не меняются,
         сервер может работать. В конце - «restore check ok» или «RESTORE CHECK FAILED» и причины.
     desk.bat restore desk-20261023-203000-nightly.dump
       - то же для конкретной копии: имя файла из папки копий или полный путь к файлу.

   УЧЕНИЕ ПО ВОССТАНОВЛЕНИЮ (раз в месяц и после обновления программы, 5 минут):
     1) Настройки -> «Резервные копии» -> «Проверить восстановление» (или desk.bat restore).
     2) Должно быть «восстановление проходит, N строк ... совпали с копией». Нет - пришлите текст
        ошибки и файл диагностики (раздел 8).
     3) На другом компьютере (чистая установка): распакуйте архив программы, один раз запустите
        start.bat и закройте его окно (stop.bat), скопируйте файл копии и рядом лежащий .json,
        затем  desk.bat restore ПУТЬ\К\ФАЙЛУ.dump --replace  (ниже), снова start.bat - на мониторах
        те же даты прогонов и позиции, что на рабочем компьютере на момент копии.

   ВОССТАНОВИТЬ ДАННЫЕ ИЗ КОПИИ (испортилась база, удалили лишнее, новый компьютер):
     1) stop.bat (или закройте окно start.bat): пока сервер работает, команда откажется.
     2) desk.bat restore desk-20261023-203000-nightly.dump --replace
        - restore ФАЙЛ - из какой копии (без имени - самая новая);
        - --replace    - после успешной проверки заменить рабочие данные копией.
        Команда сначала проверяет копию (как выше), потом показывает, сколько строк в копии и сейчас,
        и спрашивает: напечатайте  restore  и Enter (другое - отказ, ничего не меняется). Затем она
        делает копию текущих данных (desk-...-pre-restore.dump, хранятся 3 последние) и только после
        этого ставит проверенные данные на место рабочих. Прежняя рабочая база остаётся рядом
        (desk_before_restore) до следующего восстановления.
        - --yes - не спрашивать (для сценариев; вручную не нужен).
     3) start.bat. Всё, что было записано после времени копии, придётся загрузить заново: отчёты
        из папок автопилот перечитает сам, пересчёт прошлых дат - тоже.
   Ошибочно восстановили не ту копию - так же восстановите desk-...-pre-restore.dump.
   В копию базы не входят файлы папки данных: settings.json, токен хаба, adapter-config, снапшоты.
   Для нового компьютера перенесите их копированием папки данных (раздел 7) или задайте заново.

8. ЕСЛИ ЧТО-ТО НЕ ТАК
   - Диагностика для агента: Настройки -> раздел «Диагностика» -> «Собрать диагностику»,
     затем «Скачать» или «Скопировать». В файле нет позиций, книг, ISIN, сумм, путей и паролей.
     Из командной строки: desk.bat diagnostics --out diag.json
   - Журналы: %LOCALAPPDATA%\DeskMonitor\logs (serve.log, autopilot.log, update.log).
   - Проверка отчётов без базы (печатает только количества и коды, без данных):
       desk.bat adapter check --dir C:\путь\к\папке\отчётов
   - Проверка хаба:  desk.bat hub-check
   - Ошибка 407 от прокси = прокси требует вход NTLM/Kerberos, так подключиться нельзя.
     Обходной путь - папка ручной загрузки снапшотов (snapshot_drop), см.
     app\INSTALL_BACKEND_WINDOWS.md, раздел «Если что-то не так».
   - Перезапустить сервер: Настройки -> «Доступ из сети» -> «Перезапустить сервер».
   - Остановить всё: stop.bat.

9. ДОСТУП КОЛЛЕГАМ ПО СЕТИ (по желанию; по умолчанию Desk Monitor открыт только на этом компьютере)
   Коллеги открывают монитор в своём браузере по имени или адресу этого компьютера и входят
   под своими именами и паролями. Пароли хранятся только в виде хэша (Argon2id).
   Всё делается на странице настроек, командная строка не нужна. Права администратора Windows
   нужны только для брандмауэра (шаг 4) - для него страница даёт готовый текст для ИТ.
   Командная строка осталась запасным путём - в конце раздела.

   Шаг 1. Себя - администратором: Настройки -> «Пользователи» -> «Новый пользователь»:
     имя для входа латиницей (например ivanov), «Как показывать» (Иванов И.), роль
     «администратор», пароль не короче 8 знаков; для себя галочку «сменить при первом входе»
     снимите. Другой способ: на этом компьютере http://127.0.0.1:8100/login.html - пока
     администратора нет, там форма «Первый администратор» (с других компьютеров её нет).

   Шаг 2. Коллеги: там же - имя, роль, временный пароль; при первом входе коллега задаст свой.
     Роли: просмотр (все страницы), трейдер (+ точные сценарии, кнопка «Обновить» автопилота,
     свои названия бумаг ✎), администратор (+ настройки, адаптер, обновления, пользователи).
     Там же у каждого: сменить роль, «Сбросить пароль», «Снять блокировку», «Отключить»
     (вход запрещён, запись остаётся), «Удалить». Последнего администратора и себя самого
     отключить или удалить нельзя - чтобы никто не остался без доступа.

   Шаг 3. Включить доступ: Настройки -> «Доступ из сети» -> «Настройки доступа»:
     - «Доступ коллегам» - включить;
     - «Шифрование» - HTTPS (рекомендуется). Сертификат создаётся сам; браузер коллеги один раз
       предупредит «Подключение не защищено»: «Дополнительно» -> «Перейти на сайт».
       HTTP без шифрования не советуем: пароль идёт по сети открытым текстом, на каждой странице
       жёлтое предупреждение;
     - «Порт» - обычно 8100; «Адрес» - «все адреса этого компьютера»;
     - «Настройки с других компьютеров» - может ли администратор открывать настройки, обновления
       и пользователей со своего компьютера (выключено - только на этом);
     - кнопка «Применить и перезапустить». Сервер перезапустится сам (10-30 секунд; если идёт
       расчёт - дождётся его конца), страница откроется по новому адресу (https://127.0.0.1:8100)
       и попросит войти под администратором из шага 1.
     Если с новыми настройками сервер не запустится (порт занят, сертификат не подошёл), он сам
     вернёт прежние, а на странице будет причина. На этом компьютере Desk Monitor открывается всегда.
     Без администратора кнопка не сработает: с доступом из сети включается вход по паролю.
     «Только сохранить» - записать сейчас, а перезапустить позже кнопкой «Перезапустить сервер».

   Шаг 4. Открыть порт в брандмауэре Windows (один раз; нужны права администратора Windows):
     «Доступ из сети» -> «Брандмауэр Windows» -> «Скопировать для ИТ» - готовый текст заявки
     с командой; вставьте в письмо или заявку в ИТ. Там же видно, есть ли правило.
     Если права есть: Пуск -> cmd -> правой кнопкой «Запуск от имени администратора», затем
       cd /d C:\DeskMonitor
       desk.bat firewall add
     Она выполняет (то же можно ввести вручную):
       netsh advfirewall firewall add rule name="Desk Monitor (TCP 8100)" dir=in action=allow protocol=TCP localport=8100 profile=domain,private
     - name=...       - название правила (видно в «Брандмауэр Защитника Windows» -> «Дополнительные параметры»);
     - dir=in         - входящие подключения (к этому компьютеру);
     - action=allow   - разрешить;
     - protocol=TCP localport=8100 - только порт Desk Monitor;
     - profile=domain,private - в сети организации и частной сети, не в общественной (кафе, гостиница).
     Только из своей подсети: desk.bat firewall add --remoteip localsubnet. Убрать правило:
     desk.bat firewall remove. Если ИТ закрывает порты на уровне сети - им нужен этот же порт
     (TCP 8100) к этому компьютеру. Сменили порт - правило нужно на новый.

   Шаг 5. Адреса для коллег: «Доступ из сети» -> «Адреса для коллег», кнопка «Скопировать» у адреса
     (обычно первый - с именем компьютера, https://ИМЯ-ПК:8100/). Отправьте его коллегам.
     Компьютер должен быть включён и окно start.bat открыто, пока коллеги работают
     (запуск службой Windows без входа в систему - в следующих версиях).

   Перезапустить сервер (после правки настроек, если страница пишет «Изменения ещё не действуют»,
   или просто если что-то зависло): Настройки -> «Доступ из сети» -> «Перезапустить сервер».
   Окно start.bat остаётся открытым, страница обновится сама. Без страницы: stop.bat, затем start.bat.

   Проверить: «Доступ из сети» -> «Проверка доступа» -> «Проверить сейчас» (то же в командной
   строке: desk.bat lan status, во втором окне cmd в папке программы, пока Desk Monitor запущен).
     Показывает:
     - вход по паролю, адрес и порт сервера (0.0.0.0 - все адреса этого компьютера, 127.0.0.1 тоже);
     - HTTPS и сертификат - до какой даты и на какие имена и адреса он выписан; «нет в сертификате» -
       адреса этого компьютера, которых в нём нет (браузер коллеги предупредит; новый сертификат:
       «Доступ из сети» -> «создать сертификат заново» -> «Применить и перезапустить»);
     - правило брандмауэра «Desk Monitor (TCP 8100)» - есть или нет (смотрит netsh ... show rule,
       права администратора не нужны);
     - адреса для коллег;
     - проверку запущенного сервера с этого же компьютера, без прокси: сначала 127.0.0.1, потом
       каждый сетевой адрес. Для каждого одно из:
         ok (отвечает)            - этот Desk Monitor отвечает на адресе;
         no_response (TCP есть, ответа нет) - соединение установлено, но никто не отвечает:
                                    порт на этом адресе держит другой процесс (старый экземпляр,
                                    другая программа) или соединение перехватывает антивирус;
         other_server             - отвечает другой сервер, не этот Desk Monitor;
         tls_error (ошибка HTTPS) - на адресе сервер без HTTPS или чужой сертификат;
         refused                  - порт на адресе никто не слушает (сервер не запущен или
                                    новые настройки ещё не применены перезапуском);
         timeout                  - соединение не устанавливается (брандмауэр, VPN, сеть).
       Под каждой неудачной строкой - подсказка, что делать.
     Та же проверка идёт сама при каждом запуске: строки «проверка адреса» в окне start.bat и в
     logs\serve.log, и «проверка при запуске» на странице.
     Проверка с этого же компьютера не проходит брандмауэр Windows: «ok» значит, что сервер отвечает
     на сетевом адресе; если коллеги всё равно не открывают - правило брандмауэра (шаг 4) или прокси
     в их браузере (адрес - в исключения прокси: Свойства браузера -> Подключения -> Настройка сети).

   Если коллеги не открывают, а на этом компьютере https://127.0.0.1:8100 работает:
     1) «Проверка доступа» -> «Проверить сейчас» - что показано для сетевого адреса (см. выше);
     2) netstat -ano | findstr :8100 (в cmd) - ВСЕ строки LISTENING. Нормально - одна строка 0.0.0.0:8100
        (или ваш адрес и 127.0.0.1). Лишняя строка с вашим адресом или чужим PID (последняя колонка;
        имя процесса - Диспетчер задач -> Подробности) - порт держит другой процесс: закройте его
        или возьмите другой порт;
     3) curl.exe -kv --noproxy "*" https://ВАШ-АДРЕС:8100/health/live
        - -k - не проверять сертификат (он самоподписанный); -v - показать каждый шаг;
          --noproxy "*" - мимо прокси. Ответ {"status":"ok"} - сервер отвечает. «Connected», а дальше
          тишина - ответа нет (как no_response). Повторите с https://127.0.0.1:8100/health/live: если и
          там тишина - завис сам сервер: «Перезапустить сервер» (или stop.bat, start.bat) и пришлите logs\serve.log;
     4) другой порт: «Доступ из сети» -> «Порт» 8443 -> «Применить и перезапустить»
        (правило брандмауэра - на новый порт, шаг 4);
     5) свой адрес вместо 0.0.0.0: «Адрес» -> «только 10.1.2.3» (ваш адрес из списка) -> «Применить
        и перезапустить» (сервер будет слушать этот адрес и 127.0.0.1; если порт на этом адресе занят
        другим процессом, страница скажет об этом и ничего не изменит);
     6) без HTTPS, только чтобы понять, не мешает ли HTTPS (антивирус с проверкой HTTPS):
        «Шифрование» -> «HTTP без шифрования» -> «Применить и перезапустить», коллеги открывают
        http://... ; потом верните HTTPS.
   Вернуть «только этот компьютер»: «Доступ из сети» -> выключить «Доступ коллегам» -> «Применить
   и перезапустить» (вход по паролю остаётся; галочка «тоже выключить» - и его выключить).
   Забыли пароль: другой администратор - «Пользователи» -> «Сбросить пароль». Единственный
   администратор - командой desk.bat user passwd ivanov. Заблокирован после 5 неверных паролей
   (15 минут): подождать или «Снять блокировку» (desk.bat user unlock ivanov).
   Кто что делал (входы, настройки, обновления, перезапуски, доступ из сети, названия бумаг,
   пользователи): Настройки -> «Пользователи» -> «Журнал действий».

   КОМАНДНАЯ СТРОКА - запасной путь (Пуск -> cmd, в папке программы: cd /d C:\DeskMonitor).
   Делает то же, что страница:
     desk.bat user add ivanov --role admin --display-name "Иванов И."
       - роль: viewer, trader или admin; пароль спросят дважды (символы не отображаются);
       - --temporary - пароль временный, сменить при первом входе (для коллег);
     desk.bat user list                       список пользователей
     desk.bat user passwd ivanov              новый пароль
     desk.bat user role ivanov trader         другая роль
     desk.bat user disable ivanov             запретить вход (enable - разрешить снова)
     desk.bat user unlock ivanov              снять блокировку
     desk.bat user delete ivanov              удалить совсем
     desk.bat lan enable --self-signed        вход по паролю, сеть (0.0.0.0), HTTPS со своим сертификатом
       - --port 8443 - другой порт; --host 10.1.2.3 - свой адрес вместо 0.0.0.0;
       - --cert C:\путь\desk.crt --key C:\путь\desk.key - сертификат от ИТ вместо --self-signed;
       - --plain-http - без шифрования; --no-admin-from-network - настройки только с этого компьютера;
     desk.bat lan disable                     только этот компьютер (--auth-off - и вход выключить)
     desk.bat lan status                      проверка (--no-probe, --timeout 5, --json)
   После lan enable / lan disable нужен перезапуск: «Перезапустить сервер» на странице или
   stop.bat, затем start.bat.
